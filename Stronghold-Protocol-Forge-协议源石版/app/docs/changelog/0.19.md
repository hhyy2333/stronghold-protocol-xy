## 暂未发布

### 改：准备界面加「进入观战席」—— 场上也能去看（业主 2026-11-05）

- **需求**（业主 2026-11-05「准备界面只能从观战席进入场上，不能从场上进入观众席，加一个进入观众席」）：观战席此前
  只有一个方向——大厅「观战」进去、等待室里点「入座」上场。已经坐在场上的博士想让位去看队友，只能「离开同盟」
  再凭密钥观战。
- **做法**：`room.spectate {code}` 指名**自己所在的那一房**就是反方向——空出博士席位、改为这一房的观战者
  （`server/lobby.js sitOut`）。两个方向共用同一条意图，`code` 仍然必填，协议形状一个字没动（不是新增 C2S，
  `PROTOCOL_VERSION` 不抬）。
  - 只在大厅（对局进行中 ⇒ `ROOM_STARTED`：那等于中途离开这一局，走「离开同盟」）。
  - 座位照常释放，**其余人保留就绪状态**；房主让位把创建者身份移交下一位真人（与房主离开同一条 `migrateHost`）。
  - 三处点名拒绝：观战席满了 `ROOM_FULL`；会让房间一个玩家都不剩（solo 房唯一的博士、co-op 最后一名真人）
    `BAD_TARGET`（否则房间立刻被当作空房回收，点「去看」不该把房间关掉）；对局中 `ROOM_STARTED`。
- **界面**（`public/js/screens/room.js`）：等待室的观战席条对已就座的玩家也出现，多一颗「进入观战席」；点下去先问
  一句（房主那一条多讲「创建者身份移交」）。入口给不给由 `canSitOut` 判，与服务端守卫同一份读法。
  四个语言包补齐三条词条（进入观战席 / 两条确认文案）。
- **测试**：`test/lobby.test.js` 新增一条（让位 / 观战席位 / 别人仍就绪 / 房主移交 / 入座拿回原座位 / 三条拒绝），
  原来那条 `ALREADY`（「a player never switches in place」）按新口径撤掉；`test/client-static.test.js` 新增
  `canSitOut` 用例。**golden 不移动**：纯大厅与界面。
- 文档：`docs/design/network.md` §8.1（观战席那一段）、`docs/design/client.md`（Room 屏）、`docs/PLAYING.md` §8、
  `docs/history/0.3.3.md` §40.14。
