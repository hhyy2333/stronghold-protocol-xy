### 改：给【尸山】装备加「免疫晕眩、冻结等特殊状态」（业主 2026-11-04）

- **需求**（业主 2026-11-04「给尸山装备添加免疫晕眩和冻结等特殊状态」）：三阶协议源石【尸山】发放的装备
  （`chess_item_9_95_e_a`，合成后的 尸山·极 `_b`）只加属性与回血，被控住就白给。业主给的措辞与【浓缩嗅盐】
  `chess_item_4_10_e` 的卡面一字不差（「免疫晕眩、冻结等特殊状态」），所以按**同一张表**实现。
- **做法**：装备自己的战斗行为（`server/sim/content/items/protocol.js corpseHill`）挂一条 `beforeStatus` 钩子，
  装备者身上取消「特殊状态」。表只有一份：`server/sim/buffs.js` 新增导出 `SPECIAL_STATES`（晕眩 / 冻结 / 沉睡 /
  浮空 / 麻痹），【浓缩嗅盐】原来的私有 `CC` 集合改成读它 —— 两件装备从此不会各写一份而漂移。
  - **装上就生效**：钩子在装备装上时注册，不等到 `battleStart` 吃完队友；尸山·极 是另一条记录、同一段行为，
    所以它同样免疫（两件都钉了测试）。
  - **寒冷不算**：它是减益、不是控制状态，照常挂上；只是它与第二层寒冷成对转成的 `freeze` 会被这道钩子取消。
    束缚 / 沉默 / 恐惧 / 缴械 / 停顿 / 减速 / 缚地 也不在表里（与浓缩嗅盐的既有口径逐条相同）。
- **卡面**：`tools/build-data.mjs` 两条装备记录与 `tools/hextech/roster.mjs` 的 `hex_corpsehill` 都补一句
  「装备者免疫晕眩、冻结等特殊状态」，`data/items.json` / `data/hextech.json` 由工具重新生成；
  `public/i18n/en.json` 的卡面 msgid 同步换新。
- **测试**：`test/content/items.test.js` 新增「尸山 (9_95) 免疫」—— 两件装备各一条（五个状态全部被取消、寒冷照挂、
  第二层寒冷不再转成冻结、束缚照挂、卡面写着这句），外加「没装这件装备的干员照常被晕眩」。
  把 `beforeStatus` 那条钩子收走时这条会红（已验证）。
- **[ASSUMED]** 业主只点了「晕眩和冻结等特殊状态」、没有逐条列：沿用浓缩嗅盐同一条卡面文字在
  `docs/research/04-items.md` §4 的读法（晕眩 / 冻结 / 沉睡 / 浮空 / 麻痹），不扩大成「所有控制状态」。
