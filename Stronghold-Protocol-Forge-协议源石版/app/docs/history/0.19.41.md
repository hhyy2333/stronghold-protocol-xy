## 41. 融合版 0.3.3 汲取：开场演出与皮肤决策层

两条都只动客户端，`server/**`、`data/**`、`shared/**`（除 `shared/modSurface.js` 的一行元数据）与任何协议帧都没变 ——
`room.appearance` 是 0.19.41 之前就有的既有消息。

### 41.1 开场演出（`ui/allianceScene.js` + `ui/lobbyIntro.js`）

- **是什么**：不是视频，是**逐帧重放的 DOM 动画** —— 按官方活动录屏（30 fps）打表、用单调三次插值算出每帧的位移/缩放/
  透明度，画在 1280×720 的舞台上，外框是一个顶层 `<dialog>`。整段 ≈2.8 s（时间表 1.2 s 起、3.45 s 起淡出、4.0 s 结束）。
- **什么时候播**：每次打开页面一次，`main.js` 在首帧画出来之后调一次。**不播**的六种情形：路由是 `room` / `game`、
  `ui.pendingJoin`（带 `?room=` 邀请）、`ui.restoring`（刷新后正在等服务端重推对局）、手机竖屏（等转横屏、转过来再判一次）、
  系统里关了动效（`ui/device.js reducedMotion()`）、偏好 `sp.pref.lobby.intro === false`。
- **素材没下载齐就不播**：判据是 8 张入场贴图**全部 decode 成功**（`preloadSprites()` → `{ asked, loaded, missing }`）；
  缺一张就静默返回，标题页照常（本仓标题页本来就有 CSS / SVG 兜底）。这一条是移植时**唯一的真技术活**：来源那棵树
  的 `resourcesReady()` 恒 `true`（上游素材由服务器发），照抄会让没下素材的机器黑 2.8 s。
- **声音是尽力而为**：入场音效排在录屏的 1.686 s，大厅音乐从 2.144 s 起走 `audio.lobbyMusicOverride('lobby')`。
  本仓的 `audio.ctx` 是**首次手势才创建**的（`audio.js _unlock`），所以全新打开页面通常还没有上下文 ⇒ 片子静音放完，
  点一下即跳过；环境允许自动播放时（启动器 / WebView2）才出声。**没有**「点击进入 / TAP TO START」闸门：来源的
  `PACKAGING.md` 还写着要点一下，但它的代码早已改成主动 `resume()` + 500 ms 静音兜底（以代码为准）。
- **与来源的差异**（按 C 报告 §2.4 / §6，逐条有意）：① 删掉 `mountAllianceBackdrop` 那套「盟约 20 s 昼夜循环」约 65 行
  —— 它在来源里是**死代码**（零调用点），业主也已用官方「始发」整图取代这一类"重建背景"；② 不做 `whenResourcesReady`
  的等待入口（就绪判定由 `preloadSprites` 自己产出，再留一个等待入口是循环依赖）；③ 用 `audio.lobbyMusicOverride`
  而不是来源的 `audio.lobbyTrack`（那个字段本仓没有；等价物只有这一条，且它内部已经把「玩家自选音乐 / 暂停 / 在不在音乐区」
  全判过）；④ 保留片尾那 0.35 s 的「假大厅」层（本仓标题背景就是同一套 `entry/bkg_01` 素材，接缝比来源更顺）。
- **回退**：删 `ui/lobbyIntro.js` + `ui/allianceScene.js` + `main.js` 那两行；或者只写 `sp.pref.lobby.intro = false`。
- **i18n**：新增一条 `点击跳过`。片子里 `STRONGHOLD PROTOCOL` / `ALLIANCE` / `AB1–AB4` / `INPUT ▸` 等按**美术文字**
  处理（与 logo 同性质，行宽是靠录制帧量出来的），不走 `t()`。

### 41.2 皮肤决策层（`ui/skins.js` + `ui/skinProvider.js` + `ui/skinPicker.js`，并收窄 `ui/portraitChain.js` 一条边界）

这条通道在 0.19.41 之前**三面都通、只缺决策**：数据（`pack.json.skins` → `assets.skins[<charId>]`，`mergeWorkshopSkins`）、
解析链的步骤 0（`appearanceFirst`）、协议（`room.appearance` 服务端存 + 全房广播）全都在，但**没有任何 UI 能选、
没有任何东西去问提供者**（`ui/skins.js` 15 行 shim、`ui/skinPicker.js` 4 行 shim、`settings.skinByChar` 只在一行注释里）。

- **清单**：`availableSkins(charId)` 只收**真有图**的时装（`art` 里有 `avatar` / `avatarE2` / `portrait` / `portraitE2`）。
  局内 Spine 换装是另一刀（`assets.js spineEntry` 今天不认 `skin`），一套只带模型的时装选上去什么都不会变，
  把它摆进选择器就是承诺一件做不到的事。
- **选择**：`{ <charId>: skinId }` —— 键是**干员**不是棋子（`assets.skins` 按干员分组）。持久化在 `sp.pref.skins`。
  旧 shim 的注释写的是「chessId → skinId」，但那时没有任何 UI 写过它，所以没有要迁移的既有数据；`loadout.js` 的
  导出/导入 payload 里 `skins` 的键随之从棋子变成干员。
- **发帧**：`room.appearance { picks }`，改动去抖 500 ms、进房间/重连在 `room.state` 之后重发一次、**只在房间上下文发**；
  清空选择发 `{ picks: {} }`（协议上合法，语义是「我没有任何换装」，撤回上一次）。
- **提供者**：内置的那个在开机时注册（`screens/loadout.js` → `ui/skinPicker.js` 的 import 链），只答**被问的那一条 kind**。
  **有意后果：外观只走一条通道 = 工坊包** —— 插件面板再导出 `appearance(ctx)` 会被 `extensions.js` 的
  `CLIENT_APPEARANCE_TAKEN` 点名拒绝（面板照常挂载，只是画不了外观）。本树的插件 overlay 那条路本来就没实现
  （`shared/plugins/visual.js` 的 `skins` 零命中），所以这不是把一条能用的路堵上，而是不让第二条半成品路将来抢同一个槽位。
- **⚠️ `ui/portraitChain.js` 的 `explicitVariant` 收窄（本次唯一的行为改动）**：从前它在问提供者之前有三条短路 ——
  `variant: 'elite'`、`id` 以 `_1` / `_2` 结尾、`kind: 'portrait'` 且 `chess.isGolden`。而 `data/chess.json` 里
  **262/262 张立绘的 `assets.portrait` 全都以 `_1` / `_2` 结尾**、精锐棋子的 `assets.avatar` 也全是 `_2` ——
  于是步骤 0 对**每一张立绘**都短路：提供者装好了、玩家也选了时装，画面一个字节都不动（症状是「干员调配列表的头像变了、
  详情页立绘没变」）。现在只留 `variant: 'elite'` 一条：那两条是**数据给版本编号的方式**与**详情页画精锐的既有语义**，
  不是调用方的意图；玩家主动选了一套时装就该画那一套，提供者回 `null` 时链照旧回落，**失败方向不变**。
  两条不变量由测试钉住：① 开关关掉 / 调用点 `skins: false` / 没有提供者 ⇒ 262 个棋子的 `portraitUrlOf` 与
  `avatarUrlOf` 与 `chessPortraitUrl` / `chessAvatarUrl` **逐项相等**，且提供者一次都不被问；② `variant: 'elite'`
  ⇒ 与没有提供者时逐字相同。注释里留了「2026-11 改过一次，别再改回去」。
- **界面**：「皮肤」区在干员调配的详情面板里（`SkinSection`），复用 `css/screens/loadout.css` 里早就写好却一直没人用的
  `.lo-skin*` 那组样式，**不新增 CSS**；没有可选时装时整块不渲染（与 0.19.41 之前逐字相同）。显示判据是**逐干员**的
  （本仓的内置提供者不是可装可卸的插件，没有「插件没加载」这个歧义；来源用的是全局规则）。
- **回退**：玩家关设置里的「工坊外观」（`settings.workshopSkins`，默认开）⇒ 链的步骤 0 整段不存在；维护者删掉
  `skinPicker.js` 末尾那次 `installBuiltinSkinProvider()` ⇒ 槽位空出来给插件面板；彻底回退 = 删 `skinProvider.js`
  与两处 import（回到 15 行 shim 的行为，`data/*.json` 一个字节都不用改）。
- **i18n**：新增 `皮肤` / `时装` / `{n} 套外观` / `选择皮肤` / `使用中` / `干员本体，不使用时装` / `点击选择这套外观` /
  `点击回到默认外观`（`默认` 仓里已有）。

### 41.2b 内容：`workshop/official-skins/` 官方时装包（头像 + 半身像 + 局内模型）

决策层通了之后，这套机制在仓库里是**空的** —— 没有包就没有可选方案，「皮肤」区永远不出现。这一个包把内容补上，
形状沿用 §28.28：`content: []` + `skins[]`，落点 `assets.skins[<charId>]`。

- **规模**：融合版那份外观插件覆盖 302 套 / 193 名干员；按本仓 `data/assets.json` 的现有干员过滤后
  **276 套 / 174 名干员**（19 名干员本仓还没有素材，跳过）。552 张 WebP（每套 头像 180×180 + 半身像 180×360）≈ 9.8 MB。
  上游把 `avatarE2` / `portraitE2` 直接指向同一张图，照搬 —— 本仓链的「精锐」分支读的就是这两个字段。
- **形状转换**（不是改文件名就行）：上游插件是 overlayer，`assets.json` 的
  `chars[<charId>].skins[<上游 id>] = { name, avatar, avatarE2, portrait, portraitE2, group }`，其中上游 id 长成
  `char_498_inside@kitchen#2`（`@` / `#` 本仓 `SKIN_ID_RE` 不收）；本仓是 `pack.json.skins[]`，`art` 与 `art.chars` 同形、
  **包内相对路径**。脚本把 id 归一成「干员尾段_时装尾段」（`inside_kitchen_2`，超 32 字符用稳定短哈希兜底），
  `group` 进 `series`。
- **素材位置**：必须落在 `<包>/assets/` 下 —— `/workshop-assets/<包>/<assets 内的相对路径>` 这条既有路由只从这里读
  （`server/http/static.js`），放包根会 404。清单里仍写 `skins/x.webp`，装载期由 `mergeWorkshopSkins` 改写成绝对 URL。
- **局内模型**（§41.2c 的内容那一半）：同样 276 套，`art.spine = { front, back? }`，**1641 个文件 / 302.7 MB**
  （271 套有 Back 面、5 套单面只写 front；骨架全部 Spine 3.8.99）。来源是融合版的 `official-skins-models-1/2/3`
  （93 / 181 / 2 套）。每条 spine 带 `anims` / `animations` / `hits`：`anims` 由 `tools/assets/anim-roles.mjs` 的
  `resolveRoles` 对**这套骨架自己**算出（参数与官方 `chars` 条目同一套），并与融合版 `plugin.lock.json` 记录的
  anims **逐字节对账 547 个面全部一致**。**必须带 `anims`**：`assets.js validSpine()` 要 `skel`+`atlas`+`anims`，
  缺了就是「没有模型」、换装静默回落原版。融合版源里 552 个 atlas **都没有 `size:` 行**，拷贝时按本仓既有做法补上
  （我方已发 861 个 atlas 全有）。
- **不进 git**：`AGENTS.md`「No game art in git」⇒ `app/.gitignore` 单独忽略 `workshop/official-skins/assets/`，
  `pack.json`（**1.36 MB**：anims 407 KB + animations 116 KB + hits 64 KB + 路径 116 KB）与 `PROVENANCE.md` 入库
  （实测 `git status --porcelain -uall` 只有这两行）。重建：**先图后模型**
  —— `node .scratch/make-official-skins.mjs`（图 + 元数据基线）→ `node .scratch/make-official-skin-models.mjs`
  （只给已存在的 `skins[]` 补 `art.spine`）。两个脚本在忽略目录里、不随包发，共用同一条 `skinId()` 规则。
- **验证**（真服务器，端口 3013）：`node tools/workshop-validate.mjs workshop/official-skins` → 0 error / 0 warning
  → `VALID: the engine accepts this content`；`/data/assets.json` 的 `assets.skins` 有 **174 名干员**，
  条目带 `pack` / `id` / `name` / `series` 与改写成 `/workshop-assets/official-skins/skins/*.webp` 的 `art`；
  `/workshop-assets/official-skins/skins/char_003_kalts_boc_6.webp` → **200 `image/webp` 12250 B**，
  `p_char_003_kalts_boc_6.webp` → **200 `image/webp` 21796 B**。
- **回退**：`pack.json` 里写 `"enabled": false`（装载期跳过并响一声）或直接删目录；两者都不动 `data/*.json`。
- **没做**：时装语音（融合版把语音放在插件里，涉及官方语音许可与体积，单独一刀）。

### 41.2c 局内换装：`spineEntry(m, id, { skin })` 与座位外观（引擎那一半）

内容进来之后，缺的是「棋盘上用不用」：`assets.js spineEntry(m, id, opts)` 以前只认 `chars[id].spine`，
渲染侧 `render/units.js` 也就永远画官方模型。

- **契约**：`opts.skin` 认三种形状（整套 `art` / `{ spine }` / sides 本身），只在 `chars` 分支生效，`back` 缺失
  回落 `front`。**「能不能用」只看 `art.spine.front`**（新导出 `spineSides()` 作为唯一判据，判据仍是
  `validSpine`：`skel`+`atlas`+`anims`）—— 正面不成形就整份不算、回落原版，否则朝向一变会出现
  「官方正面 + 时装背面」的换人混搭。`hasBackSpine()` / store 的 `hasBack()` 透传同一个答案，单面时装因此
  **没有** Back 模型，而不是拿 front 硬顶。
- **数据通路**（不动 `server/**`、不加 `UnitInfo` 字段）：`info.ownerId` 就是座位的 `playerId`
  （`server/match/PlayerState.js` → `server/sim/snapshot.js unitInfo` → `render/app/info.js renderInfo` 原样带）
  ⇒ `store.get().room.seats[].appearance.picks[<charId>].skinId` ⇒ `assets.skins[charId]` ⇒ `art.spine`。
  新增 `render/skinSpine.js`（211 行，纯查询、依赖可注入）：`picksOf` / `skinRecord` / `outfitOf` / `appearanceGen`。
  自己那一半：本机 `sp.pref.skins` **优先**（点了立刻生效，不等 500 ms 去抖 + 广播），房间那份兜底；备战棋子
  （`pieceInfo` 没有 `ownerId`）视为自己的。
- **缓存不串**：`assets.js` 的 `spine.acquire(entry.skel, …)` 键就是 `entry.skel` URL，没有第二把「skeleton id」
  键 ⇒ 同一干员两套时装 = 两个骨架目录 = 两条记录。这条反过来是**内容纪律**：每套时装必须自带骨架目录。
- **41 套非 `Attack*` 不需要特例**：`render/spine.js` 的 `this.roles = entry.anims`，`_attackClip()` 播
  `roles.attack.loop`，代码里没有「按名字找攻击 clip」的路径（只有 idle 兜底才按名字），所以 23 套编号式
  （`Attack_A` / `Attack_1` / `Attack01`）与 16 套借用 `Skill_*_Loop`（`via: 'attack'`）都照各自 anims 跑；
  2 套 `Attack_Start/Loop/End` 也由 roles 表达。
- **热更新**：`appearanceGen()` 在房间 picks 变化时 +1，`render/units.js update()` 每帧比一次整数，变了就走既有
  `retryAssets()` 重解析 —— 队友在对局里换装无需重开。
- **测试**：`test/render/spine-skin.test.js`（11 条，含**真内容**一条：读盘上的 `pack.json` + `data/assets.json`，
  本仓认识的 271 套逐套过 `spineEntry`、5 套单面正确回落、`hasBackSpine` 与之一致、skel/atlas 同名同目录）与
  `test/render/skin-spine.test.js`（12 条：座位 picks → 时装模型、空 picks / 包里没有该 skin → null、代数语义）。
- **明确没做**（都在本文件 §41.4 记着）：`render/artWarm.js` 预热仍是官方模型（时装模型要等首次出现才下载）；
  菱形占位图仍用官方头像（`textures.js diamondTexture` 的键是 `id|url`，要先放宽键才不会串图，**只做一半就是图片层的
  串图 bug**，所以宁可不做）；`ui/skins.js availableSkins` 仍只收「有图」的时装。

### 41.4 明确**没做**的（留给下一刀，见总纲）

  正是 `blob:` URL；探针在 `app/.scratch/csp-blob-probe.mjs`（改一处 + 同步改 `test/csp.test.js`）。
