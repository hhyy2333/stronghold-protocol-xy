### 40.1 搬了：规则与结算（可复现的口径）

- **§40.1.1 穿透顺序**（上游 §37.30 / PR #798）：同一件伤害上固定穿透与百分比穿透同时存在时，**先减固定（不低于 0）、再乘百分比**。
  改前先乘后减，两类穿透叠加时会**多穿透**。落点 `server/sim/damage.js mitigate()`。上游实测 288 场景动 17 个
  （艾丽妮 / 圣聆初雪 / 迷迭香 / 送葬人 / Pith 这类同类叠加）。
- **§40.1.2 重入式 buff 移除**（上游 §37.5 / round49）：`onRemove` 里再移除别的 buff 时，按索引倒序遍历 live 数组会读到
  `undefined`（崩溃）或漏掉一个匹配项。改为先做快照、再按对象身份逐条定位删除。上游 golden **0 移动** —— 是崩溃修复，不是平衡。
- **§40.1.3 攻击类技能占用普通攻击的回合**（上游 §37.19 / §37.29 / §37.52 / §37.55）：技能"触发索敌和普通攻击相同"，
  就绪时按优先级选、同级随机；**没有攻击目标就不释放**（`_allowNoTarget` 的例外照官方）；**冷却从该技能动画结束时起算**；
  技能动画比攻击间隔长时下一次普攻等动画放完。昆图斯第三形态因此变成**大潮与普攻交替**（游戏内每 7.00 s 一次，原为 3.5 s 且普攻照常），
  断裂生殖在 7 段小队动作用完后不再释放；「自在」的【破桎而出】改为**需要目标**才展开屏障。
  落点 `server/sim/content/enemies.js`（`attackSlotSkill` / `attackTurnSkill` / `castNow` / `markAttackTurn`）与 `bosses.js`。

### 40.2 搬了：对局与敌人行为

- **§40.2.1 鸭爵「神秘顾客」每回合只抽一次**（上游 §37.26 / #839）：四人的替换数量、敌人与换成的种类相同，
  从本回合自身波次（不含悬赏敌人）中选。用 `ctx.seedFor('duck:<round>')` 的独立流。
- **§40.2.2 「进入休整期时」移到机变选择之后**（上游 §37.24 / §37.53 / #851）：老鲤第 3 回合的 2 / 4 阶干员、
  `preparation_start` 类策略与干员特质的「<进入休整期时>」都改在**休整期开始**发放，不再早于机变 draft。
- **§40.2.3 隐秘核心（R15）重新配对**（上游 §37.27 / #845）：首次规划用独立 salt（`boss-pairs:15`）且 `previous: null`，
  不再沿用最终攻势的搭档；该回合备战中有人退出时只为落单者重新配对。
  **有意偏差**：上游同时"随机洗牌分组与左右"，我们**不做** —— 本仓库 2026-10-16 的业主决定是**按座位序确定式配对**
  （座位小者在左半场），随机化会让客户端缺 `bossPairs` 时的兜底 `prepPair` 把摆人卡回道中。
- **§40.2.4 凯瑟琳突变细胞每玩家每局一次**（#677）：抽卡时排除已领取者，`pickReward` 里计数。
- **§40.2.5 联防只给漏过来的那一波记账**（#675）：场上才出生的（分裂 / 召唤的）子体不再被当逃逸者抬 ×N 扣目标生命；
  运行时子体打 `uniteRuntime` 标记，leak 记录带出该标记，结算只统计原本就在这一波里的敌人。
- **§40.2.6 血珀**（上游 §37.107 / #720）、**心虚设计师**（§37.108 / #869）、**淤困**（§37.95 / #803）：
  血珀在场上没有唤血祭坛 / 沥血王座时每秒流失 10 % 最大生命（真实流失、可致死、不吃 DEF / RES / 闪避 / 屏障，仍自缚、失衡免疫、不攻击、不可阻挡）；
  心虚设计师被阻挡时正面朝向**阻挡者那一侧**（80 % 减伤跟着转），未被挡时朝走路方向，同一列的阻挡者保持上次朝向 [ASSUMED]；
  淤困附着时**闪现到阻挡者格心并自缚**。朝向与瞬移的客户端半边见 §40.3.4。

### 40.7 业主 2026-11-01 裁定：【不区区！】不屈干员之间不相互分担

业主原话：「不区区的效果有问题不屈干员之间不应该相互分担」。2 阶普通协议【不区区！】`hex_sharepain`（卡面 `desc` /
`params.sharePain` 在 `tools/hextech/roster.mjs`，战斗半边在 `server/sim/content/hexcards/batch10.js`
`installSharePain`）的分担判定补一条闸：

- **旧行为**：任何己方干员受到伤害，只要场上有另一名〖不屈〗干员，就把 `pct`（默认 50%）转移给它 —— 挨打的**本身就是
  不屈**时也照样转移，于是变成「不屈替不屈挨刀」，两边都在掉血，看起来像卡没生效。
- **新口径**：挨打的那名**自己就是〖不屈〗干员**时，这一发**完全不分担**（既不转移、也不补血）；分担只发生在
  「非不屈干员挨打、由一名〖不屈〗替它吃 `pct`」这一种情形。判定用 `isMember(battle, unit, 'indomShip')`（与盟约内容
  同一判据：数据盟约 ∪ 装备 / 特质授予 ∪ 盟约共鸣借来的）。
- 卡面文字不变（「不屈干员会为其他干员分担 50% 的伤害」本就不承诺不屈之间互保），所以 `public/i18n/*` 与卡面 desc 不用动。
- **回归**：`test/sim/hextech-battle.test.js` 新增
  「不区区！(sharePain, 2026-11-01): 不屈干员之间不相互分担——非不屈挨打才由不屈替它吃 50%」
  （去掉这条闸时该 test 会红，已验证）。

### 40.8 业主 2026-11-01 改口径：【复制】第一枚时保留效果

业主原话：「协议『复制』加个第一个时保留效果」。2 阶普通协议【复制】`hex_replicate`（卡面 `desc` / `effect.onPick.copyOwnedHex`
在 `tools/hextech/roster.mjs`，两半都在 `server/match/hextech.js`）。

- **旧行为**：获得时随机复制一张你已拥有的协议源石，然后【复制】自身消失 —— 但如果它是你拿到的**第一枚**协议源石，
  没有对象可复制，它照样消失，等于白拿一张卡（`test/match/hex-replicate-doll.test.js` 原来就把这条锁着）。
- **新口径**：没有可复制对象时【复制】**不消失**，留在收藏里等；之后这个玩家**再获得**一枚协议源石，就用这枚留着的
  【复制】复制**刚到手的那一枚**（不掷骰，就是它），然后它才消失（`resolveWaitingReplicate`，在 `applyHex` /
  `applyCopiedHex` 的每个目标上兑现一次）。有对象时的旧口径不变。
- 细则：每个「获得」只兑现一枚（同时留着多枚【复制】时其余继续等）；刚到手的就是【复制】本身时不动（卡面「复制一个你
  **已拥有**的协议源石」不含自己）；同一张卡每个玩家仍只有一个 ref（`addHexRef` 去重）。
- **回归**：`test/match/hex-replicate-doll.test.js` 的「第一个时保留效果」「再拿一枚不会叠出第二个 ref」两条；
  `test/match/hextech.test.js` 的盟约寄生副本那条在 setup 里先摘掉开局自带的【复制】（它现在会等到获得盟约寄生时兑现）。

### 40.13 业主 2026-11-04 改口径：【复制】只能复制「自选」的协议源石

业主原话：「能让协议源石复制只能复制自选协议吗？」。群里紧邻的一句说明了当下的毛病：
「他会先复制成队友选的全体增益的海克斯」。

- **旧行为**：【复制】`hex_replicate` 的候选池是 `ps.effects` 里**我拥有的一切** `hex:<id>` ref ——
  `server/match/hextech.js drainPendingHexCopies` 里那段 `for (const e of ps.effects)`。可这个数组里的卡不都是我
  挑的：`team: true` 的卡（【战争机器】【共鸣协议】）是**队友**在三选一里挑的，只是按 `applyHex` 的 targets 发到
  我身上；二次抽取、镜像协议、潘多拉换回来的、换牌 / 策略授予 / 测试场给的也全都不是我的选择。于是【复制】会
  把「队友选的全体增益」复制一份出来。
- **新口径**：候选池只有**我自己在三选一里挑中的**协议源石。判据是 ref 上的 `data.selfPicked`：
  - **谁写它**：`applyHex` 的 `opts.selfPicked`，而**唯一**传 true 的调用点是抽卡本身
    （`server/match/match/hexDraft.js _applyHex`）。团队卡按 targets 发到队友的那一份**不盖章**（`p === ps` 才盖）
    —— 这正是业主报的那条。副本同样不盖（`applyCopiedHex` 传 `selfPicked: false`），否则「复制 → 副本 → 再复制」
    会成为绕开新口径的链。
  - **读法**：新增导出 `selfPickedHexIds(ps)`（`server/match/hextech.js`）。候选池与「留到下一张」的兑现都走它。
  - **只升级不降级**：一张卡若先以「别人给的」身份进过收藏（无章），之后我又自己选到同一张，`addHexRef` 给已有的
    ref 补章；反过来永远不抹掉已有的自选章。
- **「留到下一张」同一条口径**（业主 2026-11-01 的保留效果）：等着的【复制】只被**一次自选获得**兑现。
  `resolveWaitingReplicate` 新增 `selfPicked` 参数，非自选的获得直接返回 0（继续留着等）。不这样收口的话，
  「留到下一张」就是绕开新口径的后门：它会替任何一张路过的卡兑现。
- **没得复制时仍然「不消失」**：手上只有别人给的卡时【复制】留着等下一次自选（2026-11-01 的口径不变）。
- **卡面**：`tools/hextech/roster.mjs` 的 `hex_replicate` desc 改写，`data/hextech.json` 由
  `node tools/build-hextech.mjs` 重新生成。**措辞按业主 2026-11-04 在群里选的口径 B**：「随机复制一个**你自己抽到的**
  协议源石」—— 不写「自选」，因为本仓库里「自选」已是「自选编队 / DIY 干员槽」的专用词，写在协议源石卡面上会让玩家
  以为在说干员。卡面 desc 不是 i18n msgid，四个语言包不动。
- **回归**：`test/match/hex-replicate-doll.test.js` 末尾四条 ——「只复制自己选的，不复制别人塞过来的」「手上只有别人
