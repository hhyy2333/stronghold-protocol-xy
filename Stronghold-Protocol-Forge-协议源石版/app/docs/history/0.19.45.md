## 42. 时装素材搬进站点素材（0.19.45，2026-11-02）

业主一句话点的方向：「先皮肤 mod 有点大了做到素材包里好导入」。

官方时装包（`workshop/official-skins/`，0.19.41 §41.2b/§41.2c 落地）一直是**包里自带美术**：`pack.json` 1.4 MB 的
数据 + `assets/skins/*.webp`（552 个 / 9.8 MB）+ `assets/spine/**`（1 641 个 / 302.7 MB），合计 **321 MB**。这一节
记的是「把这 321 MB 搬到服务器自己的素材里」之后得到的四条性质，以及搬的过程中钉住的边界。

### 42.1 为什么「放在包里」是错的

不是体积审美，是两条通道都不认它：

1. **没有长缓存。** `public/assets/` 下的文件由 `server/http/assetIndex.js` 按内容哈希（SHA-256 前 16 位）发出去，
   浏览器拿 `immutable` 存一年；而包素材走 `/workshop-assets/<包>/…`，那条路由**不在** `shared/assetPaths.js`
   的 `HASHED_ROOTS` 里（`/assets/`、`/fonts/`、`/media/` 三条），所以每个文件都只能 `no-cache` 回源验证。
2. **进不了素材包。** 「导入素材包」（`public/js/assetPack.js`）只收**服务器清单里列出、且 URL 带内容哈希**的
   文件 —— 它在导入时按 URL 里的哈希逐个校验字节。包素材的 URL 没有哈希段，所以即使玩家手里有这份 zip，
   一个文件也收不下。

一句话：`/workshop-assets/` 是「只能走网络、而且每次都回源」的通道；需要预载/导入的东西必须住在 `/assets/`。

### 42.2 做了什么

* **素材搬家**：`workshop/official-skins/assets/{skins,spine}` → `public/assets/skins/{art,spine}`
  （2 193 个文件 / 327 723 316 字节；`public/assets/` 本来就在 `app/.gitignore` 里，不入库的纪律没变）。
* **包只留数据**：`pack.json` 里每条 `art` 路径从 `skins/x.webp` / `spine/x/Front/x.skel` 变成
  `/assets/skins/art/x.webp` / `/assets/skins/spine/x/Front/x.skel`；包目录里再没有 `assets/`，于是
  `hasAssets: false`（「带素材的包必须声明 license」那条判据自然不适用，本包照旧声明 license）。
  两个生成器（`.scratch/make-official-skins.mjs` / `make-official-skin-models.mjs`）改成写站点素材根，
  仍然幂等（第二次跑报「无变化」）。
* **声明层**（`shared/workshop.js`）：`art` 与 `skins[].art` 的路径字段接受两种写法 —— 包内相对路径（既有行为，
  一个字节没动）与**站点素材路径** `/assets/…`。判据 `isSiteArtPath` 比包内路径更严：只有 `/assets/` 这一个绝对根、
  段里不许 `.` / `..` / 空段 / 反斜杠 / `?` `#` / 百分号编码穿越，**也不许自带内容哈希段**（哈希由服务器按磁盘字节算，
  写死在清单里就是一份会漂的副本）。`ART_NEEDS_ASSETS` 的判据从「声明了 art」收窄成「声明了**包内**路径」
  （`artPackPaths`，按 `ART_TABLES` 的形状走路径字段，所以 `anims` 里的动画名不会被误当成文件）。
* **合并层**：唯一的 URL 拼法 `workshopArtUrl(packId, p, prefix)` —— 站点路径原样返回，相对路径照旧拼
  `/workshop-assets/<包>/<路径>`。`workshopArtIndex`（`art.*`）与 `mergeWorkshopSkins`（`assets.skins`）共用它。
* **服务器**：合并后的 `data.assets.skins` 里是 `/assets/skins/…`，于是既有那条「合并体也要套 `rewriteManifest`」
  的分支（`server/http/static.js`，0.2.6 §33 为带宽加的那一层）自动给它们盖上内容哈希，Spine 整组共用一个
  **模型哈希**。新增两件：
  * `/room-data/<摘要>/assets.json` **也套这一层**（此前把物化好的数据原样发出）。这一份才是对局中客户端真正读的
    数据面（`public/js/battle/simLoader.js`），不套的话进了对局每一个美术 URL 都是裸路径 —— 预载按地址存，
    一个都命中不了，321 MB 每局重下。
  * **模型索引登记**：`assetViews.js siteModels` 走一遍合并体，把 `/assets/…` 的 Spine 组交给 `assetIndex.setModels`
    （`server/index.js` 的 `extraModels`）。少了它，派生出来的 atlas / 页 URL 在 `urlHashOk` 里对不上模型哈希，
    退成 `no-cache`（字节是对的，只是每次回源）—— 2193 个文件每次都回源。
* **打包**：`tools/package.mjs` 新增 `packSiteArt(root)`，把已装包声明的 `/assets/…` 并进素材包的那份 plan
  （`importableArt` 的第 4 个参数）。并进文档**之后**才走 `rewriteManifest` —— 顺序反了的话那些 URL 没有哈希，
  `planFrom` 会把它们当「不可校验」全部丢掉（症状：素材包少 2 193 个文件、不报错）。

### 42.5 部署

素材现在是**服务器素材**：两台服务器的 `public/assets/skins/` 必须有这 2 193 个文件，否则时装选择器里每一套
都会回落原版（`outfitUsable` 的既有兜底 —— 失败方向是「没有换装」，不是「白屏」）。所以本刀的上线包要把
`public/assets/skins/**` 一起带上去（华为云单槽 tar 的 `public/assets` 白名单子树、阿里云那套 `--assets` 之外的
素材同步），随后重打一份素材包（`node tools/package.mjs --assets`）：旧素材包对新的清单有 2 193 个文件的漂移，
`check-asset-pack.sh` 会如实报 13%。
