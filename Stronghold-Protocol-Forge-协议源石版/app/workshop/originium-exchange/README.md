# 源石证券交易所 · originium-exchange

> 给 Forge 版「卫戍协议：盟约」做的**炒股 mod**：工坊包形态，不改引擎一行代码。

## 这是什么

每局开一家交易所。六支「盟约概念股」跟着本局各盟约的**冷热**（有多少名玩家在玩、叠了多少层）、
**共同市场**与一回合一条随机新闻涨跌；玩家在**休整期**用对局里的**资金**买卖股票，每回合按持仓吃**分红**，
可以**借钱加杠杆**，也会**爆仓**，结算时比**总资产**排名。

> **1.3.0（2026-10-21）**：波动性翻倍 —— 单回合中位数 5.7% → 8.1%，13 次改价累计中位数 17.0% → 29.0%；
> 新增 3 回合一段的**市场情绪**（牛/熊/平静）、**源石大盘**与**追保预警**；股价区间 0.25~99.00，单回合夹 ±45%。
> 业主同日明确**不做**「股票跟着盟约层数增长轮动」的业绩机制：盟约冷热仍只按绝对层数/持有人。
>
> **1.4.0（2026-10-22）**：杠杆 **3x → 5x**（4x / 5x 各配一条自己的追保线，见下）；股价的
> **显示模式**（「保留小数」/「无小数点」＝ ×100）一颗按钮切换，偏好记在本机 `localStorage`，纯显示、不改成交额。
>
> **1.4.1（2026-10-22）**：修「下单后列表跳回最上端」。股票列表是滚动容器，而每收到一帧行情都会清空重建 ——
> 真浏览器里子节点清空的那一刻内容高度归 0，`scrollTop` 被夹回 0，再塞回同样高的内容也回不去。现在重画前后
> 记住并写回滚动位置。见下「滚动位置」。

买股票的钱就是本来要买棋子的钱 —— 这是一条真正的取舍：押对了起飞，押错了这局少一个干员。

## 为什么开市价是 1~6 块

引擎的经济**每回合重置**：`data/config.json` 的 `economy.income` 是 `0/4/5/6/…/12`，而且
`economy.leftoverFundsLost = true` —— 休整期结束时没用完的钱直接清零（只有 `band_cannot` 留得住）。
所以每股 100 块在这个经济里是**一单都买不起**的摆设（整局总收入约 130）。
1~6 块让「每回合买 1~3 股」成为真选择；杠杆让「借钱建仓、拿分红还」成为真赌注。
1.3.0 起价格可以跌到 **0.25**、涨到 **99**：开市价还是 1~6，但 KAZ 的 1.00 不再被地板锁成「只能涨」。

| 股票 | 盟约 | 开市价 | 波动 | 市场 beta |
|---|---|---|---|---|
| YAN 尚蜀重工 | 炎 | 3.00 | 1.43 | 0.8 |
| VIC 伦蒂尼姆兵工 | 维多利亚 | 2.00 | 1.65 | 1.0 |
| SIR 叙拉古食品 | 叙拉古 | 5.00 | 1.80 | 1.1 |
| KAZ 卡西米尔骑士竞技 | 卡西米尔 | 1.00 | 1.88 | 1.4 |
| KJE 谢拉格矿业 | 谢拉格 | 6.00 | 1.28 | 0.6 |
| AEG 阿戈尔深海科技 | 阿戈尔 | 4.00 | 1.95 | 1.5 |

`beta` 是这支股票对**共同市场因子**的敏感度：谢拉格矿业最稳，阿戈尔深海科技最野。

**价格保留两位小数**：整数口径下，1~6 块的股票吃个股噪声常常四舍五入成 0，行情会变成一条直线；
两位小数让 1 个百分点的波动看得见，「盟约冷热」才有意义。

## 钱的账目（1.3.1 修）

引擎的 `PlayerState.addFunds` 是**整数元**（`Math.trunc`），而本 mod 的股价是两位小数。
直接把小数金额交给引擎会被截断 —— 买入少付、卖出少收，**每一单都凭空多出不到 1 元**；
最低价 0.25 时买 1 股甚至扣 0 元，等于白拿（业主 2026-10-21 报的「股票无中生钱」）。

现在所有金额先算到**分**，再用「尾差」把不足 1 元的零头记在交易所账上（正 = 交易所欠你），
下一单抵扣。账本恒等式（有自动化测试逐笔核对）：

```
现金 + 尾差/100 − 负债
  买入 ⇒ 精确减少（成交额 + 手续费）
  卖出 ⇒ 精确增加（成交额 − 手续费）
  分红/利息 ⇒ 精确增减
```

误差为 **0 分**。

## 规则

| 项 | 值 |
|---|---|
| 交易窗口 | 只有 **休整期（PREP）**；作战/结算按钮禁用，服务端也拒单 |
| 手续费 | 成交额 ≥ 10 才收，1%（四舍五入、最少 1） |
| 分红 | 每回合「持股 × 现价 × **1.2%**」，按**万分之一元累计**（不够 1 元的部分滚到下一回合，小数不丢）；**先分红再改价** |
| 持仓上限 | 每股 **300 股** |
| 单回合涨跌 | 情绪漂移×beta + 共同市场×beta + 个股噪声 + 冷热 + 新闻，夹在 **±45%** |
| 股价区间 | **0.25..99.00** |
| 市场情绪 | 每 **3 回合**一块：35% 牛市（+2.5%/回合、波动 ×1.15）、30% 熊市（−2.5%、×1.25）、35% 平静 |
| 新闻 | 每回合 **45%** 概率一条，单股 **±10..30%**，走引擎的滚动条（`m.ticker`）全房间可见 |
| 源石大盘 | 六支 `price/base` 的等权平均，开市 100；面板行情带 + 收盘结算层都显示 |
| 大行情 | 单回合 \|涨跌\| ≥ 20% 的股票会上滚动条 |
| 追保预警 | 负债/持仓距**这一档的**追保线 −15 个百分点变黄、−5 个百分点变红；1–3 档追保 70%，4x 88%、5x 93% 服务端强制平仓 |
| 显示模式 | 股价「保留小数」（默认，两位小数，如 3.04）/「无小数点」（**×100** 的整数，如 304）；纯显示，成交仍按两位小数结算 |
| 开市 | 第 1 回合开始；第 2 回合起分红、计息、涨跌、爆仓检查 |
| 资金同步 | 休整期买棋子 / 刷新商店 / 卖棋子导致资金变化时，交易所**自动**补一帧（引擎 `flush` 之后按现金去重），不用再下一次单 |
| 出局 | 持仓作废、不再分红；收盘显示「已出局」 |

### 行情公式（1.3.0）

每回合、每支股票：

```
pct = clamp( 情绪漂移×beta + 共同市场×beta + 个股噪声 + 盟约冷热 + 新闻, -45, +45 )
```

- **市场情绪**：3 回合一块，块内方向不变 —— 行情有趋势，不是纯 IID 噪声。
- **共同市场**：80% 的回合幅度 0..5%，20% 的回合 5..15%，方向对半 —— 六支会一起大起大落。
- **个股噪声**：`(2u−1) × 8 × vol × 情绪波动倍率`；`vol` 见上表。
- **盟约冷热**：`clamp(持有人×0.8 + 层数×0.1 − 0.3, -2, +6)`（绝对层数/持有人；**不是**层数增长）。
- **新闻**：45% 一回合一条，单股 ±10..30%。

实测（300 个种子，round 2..14 共 13 次改价）：单回合 `|涨跌|` 中位数 **8.1%**（p90 19.5%，≥10% 的回合占 39.3%），
13 次改价累计 `|涨跌|` 中位数 **29.0%**（p90 71.4%），下跌收场约 53.8%。

**分红 1.2% / 利息 0.4% 是怎么定的**（两次都靠实测扫描，不是拍脑袋）：

- 分红按**全部持仓**发，利息只按**负债**收。分红率一旦高于「利率 × 负债/持仓」，借钱满仓就是
  **正期望的印钞机**（实测 5% 分红 / 6% 利息时，3x 满仓 30/30 全胜、期末 +99.4）。
- 利率反过来也不能太高：市场平均单回合才涨 **0.45%**，利率 12% 意味着每回合要赚 12% 才打平 ——
  缺口 27 倍，杠杆数学上不可能赢。实测 12% 时 1x/2x/3x/5x 是 54.4 / 31.6 / 28.1 / 20.9（单调下降，纯亏）。
- 最终 0.4% 是扫出来的平衡点（20 种子 × 9 回合）：

| 利率 | 1x | 2x | 3x | 5x | 最优档 |
|---|---:|---:|---:|---:|---|
| 0% | 73.7 | 74.3 | 72.4 | 62.2 | 2x |
| **0.4%** | **73.7** | **73.9** | **71.0** | **60.1** | **2x** |
| 0.6% | 73.7 | 73.2 | 70.4 | 59.0 | 1x |
| 2% | 73.7 | 70.0 | 66.2 | 53.1 | 1x |

  0.4% 是 2x 仍为最优档的最高利率，同时 3x / 5x 已经开始递减 —— **适度杠杆有回报、过度杠杆纯亏**。
  再高一点杠杆就全线跑输不借钱，档位形同虚设。

**持仓上限为什么从 60 提到 300**：60 才是杠杆亏钱的真正原因。实测 1x 和 2x 都在 R6–R7 撞到 60 股上限，
之后持仓市值完全一样（都是 48.6），但 2x 还背着 31 的负债 ⇒ 净资产 28.6 vs 63.4。
杠杆只帮你**更早**撞上限，然后只剩利息和爆仓风险 —— 即使利率降到 0%，2x 依然亏（33.2 vs 54.4）。
（1.3.0 只放大了波动，分红/利息比例没有重调；波动变大后 3x 更容易被强平。）

### 杠杆（1.4.0：3x → 5x）

| 档位 | 能借多少 | 追保线（强平） | 卖到 |
|---|---|---|---|
| **1x** | 0 | 70% | 50% |
| **2x** | 最多 1× 净资产 | 70% | 50% |
| **3x** | 最多 2× 净资产 | 70% | 50% |
| **4x** | 最多 3× 净资产 | **88%** | 82% |
| **5x** | 最多 4× 净资产 | **93%** | 87% |

净资产 = 现金 + 持仓市值 − 负债。

**为什么 4x / 5x 要另给追保线**：满仓时的静止担保比例是 `(L−1)/L` —— 3x 是 66.7%，刚好压在旧的 70% 下面；
4x 是 75%、5x 是 80%，都在 70% **之上**。只用旧阈值的话，4x/5x 满仓会在下一回合「一开市就被强平」，
5x 等于不存在（再加上利息资本化，5x 满仓次回合的担保比例会继续往上爬）。
所以两档各给一条更宽的线，让「满仓 + 价格不跌」物理上成立，同时不变成免费午餐：

- 5x 满仓 80%，离 93% 只有 13 个百分点 —— 一根中位数 8% 的阴线就够触线；
- 利息现在是 0.4%/回合：5x 满仓每回合约吃掉 1.9% 的净资产，主要成本变成了**波动与强平**；
- 1x / 2x / 3x 的阈值**一个字都没动**，旧手感不回归。

顺带一句：档位只决定「最多能借多少」，借多少由这一单自己决定 —— 5x 档只借 1 倍净资产，风控与 2x 相同。

- **先花现金、不够才借**：一单要 36 块而手里有 20，就借 16。
- **利息 0.4%/回合**：从现金扣；付不出就**资本化进负债**（利滚利）。按万分之一元累计，不会因为取整把小数吃掉。
- **卖出先还债**，剩下的才进现金 —— 引擎里现金每回合清零，**还债才是留住价值的路**。
- **维持担保比例按档位**：负债 / 持仓市值 超过这一档的线 ⇒ **强制平仓**（从最不值钱的那支开始卖），卖到下一档目标以下。1–3 档 70% → 卖到 ≤50%；4x 88% → ≤82%；5x 93% → ≤87%（推导见上）。
- **降档要还得起**：负债超过新档额度时拒绝降档，先把钱还上。
- 爆仓与平仓都在**服务端**执行，面板只是收到结果。

### 市场情绪、源石大盘与追保预警（1.3.0）

- **市场情绪**：3 回合一块，块内方向与波动倍率不变；块切换时上滚动条（「市场情绪转为牛市，接下来 3 回合概念股整体看涨」），面板行情带显示当前情绪与剩余回合。
- **源石大盘**：六支 `price/base` 的等权平均（开市 100）。行情带显示点位与涨跌，收盘结算层显示「本局大盘 ±X%」—— 比「股神」多一个基准。
- **大行情**：单回合 `|涨跌| ≥ 20%` 的股票上滚动条，不开面板的人也看得见。
- **追保预警**：面板显示「负债率 X% · 追保 X%」，追保阈值取**当前档位**的（1–3 档 70%、4x 88%、5x 93%）；距阈值 −15 个百分点变黄、−5 变红。

### 显示模式（1.4.0）

面板在「杠杆」下面多一行「显示」，两颗按钮：

- **保留小数**（默认，也就是 1.3.x 的样子）：股价两位小数，屏幕上的数字就是成交价 —— `3.04`。
- **无小数点**：**把价格 ×100** 之后按整数显示 —— `3.04` → `304`、`0.25` → `25`、`99` → `9900`。

为什么是 ×100 而不是四舍五入：价格本来就是两位小数口径，×100 正好把它抬成「分」，**信息一点不丢** ——
`304` 和 `3.04` 是同一个价的两种写法。四舍五入会把 `3.04` 抹成 `3`、把 `0.25` 抹成 `0`，屏幕和成交价对不上，
那才是最坏的一种显示。

这是**纯显示**：算钱、算可买股数、下单、强平全用服务端的两位小数真实价 —— 切到无小数点模式不会让任何一单少付或多收一分钱，
订单回执里的价格也仍然是真实值。偏好写在本机 `localStorage` 的 `sp.oex.priceMode`，刷新 / 下一局都还在；
读不到或值不认识时退回「保留小数」。切换不发任何网络帧（面板那一行的小字会写明「价格 ×100 · 仅显示，成交按两位小数」）。

### 滚动位置（1.4.1 修）

六支股票在窄屏 / 矮屏上放不下一屏，列表是 `overflow-y: auto` 的滚动容器。而面板**每收到一帧行情都会清空重建**
列表 —— 买 / 卖之后服务端回的那一帧回执、下一回合的行情帧、资金变化的补帧，都是这样。真浏览器里子节点被清空的
那一刻内容高度归 0，`scrollTop` 随即被夹回 0；紧接着又塞回六行同样高的内容，滚动位置也已经回不去了。

表现就是业主报的那样：**往下滚到第 4、5 支股票，买一手，列表跳回最上端**。

现在所有列表重画都走同一个入口（`renderStockList`）：重建前记下 `scrollTop`，重建后写回去 —— 顶部时不动它
（写回 0 只会白触发一次 scroll 事件）。列表变短时浏览器会把 `scrollTop` 夹到新的上限，那是期望行为。

回归用例在 `test/workshop/originium-exchange.test.js` 的「滚动位置」一组：假 DOM 的 `removeChild` 把
「清空 ⇒ scrollTop 归零」这条真行为模拟了出来，所以把修复退回去，那两条用例会立刻红。

**确定性**：行情 = `mulberry32(Match.seed, 回合, 股票 id, 盐)` —— 同一局同一种子必然同一段行情，
不读时钟、不用 `Math.random`。资金变动只走引擎唯一写口 `PlayerState.addFunds()`，随既有 `m.private` 同步。

### 入口与自动展开（1.4.3，业主 2026-10-23）

- **入口**：从 `screen.game.aside` 的右侧竖标签挪到商店栏的按钮行 —— `screen.game.shopTools`（DESIGN §28.8），
  `冻结` 的左边，与战地商店的「商店」并排。收起态是一颗与 `冻结 / 刷新` 同高的横排按钮（`.oex__tab` 改成
  inline-flex、`.48rem` 高），抽屉仍然是贴右上角的 `position: fixed`（`.oex__panel`）。
- **不再自动展开**：原来收到任何一帧休整期行情就 `applyOpen(true)`（`userCollapsed` 只是玩家手动收起后的
  一层豁免）。现在**默认就是收起**，只有点按钮才开 —— 进局 / 重连 / 回到休整期都不会替玩家弹界面。
  `applyOpen` 的第二参数与 `userCollapsed` 一起删掉了。
- 面板文件本身仍然**不改引擎**：新槽位是引擎提供的一格（与 `screen.game.shopCard` 同一套机制），
  这一包只是把 `slot` 指过去。

### 入口按钮出现时机（1.4.6，业主 2026-11-05）

业主原话：「战地商店和证券交易所这俩 mod 的进入那个按钮是在展开商店一段时间之后才刷出来，能不能优化一下他的
出现速度」。两处原因，一处都不在这个包里：

1. **宿主重建不算「状态变化」**：商店栏的 收起 / 展开 是 `public/js/screens/game.js` 的 `useState`，展开时
   Preact 把整块 `[data-mod-slot]` 换掉，而 store 一个字节都没变。注册点（`public/js/ui/extensions.js`）过去只在
   store 变化时重试挂载，于是面板要等「别人的一帧」才挂得上。现在它同时盯着 DOM（新增的
   `public/js/ui/slotHostWatch.js`）：宿主容器一出现就 `flush()`。
2. **挂载之后还等 1.2 s**：面板原来在挂载 1200 ms 之后才第一次 `pollRoom()`（→ `hello` → 服务端补一份行情）。
   现在**挂载那一帧就问**，`pollRoom` 的重试节奏不变（1.5 s 一次，上限 40 次）；行情回来之前按钮本来是隐藏的
   （`root.hidden`，只有休整期才显示），所以这一改的净效果就是「展开商店 = 按钮立刻在」。

实测（本地服务器 + 无头 Edge，1280×720，真实对局走到休整期，收起商店栏再展开）：两颗按钮 **26–40 ms** 内都
可见（面板在 6–12 ms 挂上，先「商店」后「¥ 交易所」，后者多等一帧行情）。旧版本同一场景下 150 ms 时两颗按钮
都还不在，整块面板要等到下一次对局状态变化才挂上（实测 351 ms ~ 3.8 s，且不可预期）。前后对照图与可重跑的
脚本在 `public/dev/mod-entry/`。

## 安装 / 启用 / 卸载

- **这台机器已经装好**（`app\workshop\originium-exchange\`）。**重启游戏服务器**后生效：关掉 `启动游戏.bat` 的窗口，再双击一次。

- 这是 `combat: true` 的玩法包：进房间摘要闸门，客户端会按房间自动对齐字节，所有人看到的行情与成交结果一致。

## 界面

- 入口在**商店栏的按钮行里、`冻结` 的左边**（与战地商店的「商店」并排）：一颗横排的「¥ 交易所」按钮，挂在
  `screen.game.shopTools`（DESIGN §28.8）上。**默认收起**——进局 / 重连 / 回到休整期都不自动弹面板，点一下按钮
  才开，点第二下收起（1.4.3）。
- 抽屉贴右上角（`position: fixed`，与按钮分开：按钮住在商店栏，抽屉仍占上半屏右侧）。
- 顶部：回合 / 相位 / **行情带（源石指数 + 市场情绪）** / 总资产 / 现金 / 持仓 / **负债**；新闻条；数量档位 1 / 5 / 10 / 全部；**杠杆档位 1x…5x**（含可借额度 / 负债率与追保距离）；**显示模式**（保留小数 / 无小数点）。
- **金额一律两位小数**（2026-10-25）：持仓 = Σ(股数 × 股价)，股价是两位小数（3 股 × 3.07 = 9.21），取整会把它抹成 9；
  负债虽是整数元，也补 `.00` 让两栏对齐。显示模式切到「无小数点」时金额一起 ×100，与股价同一套口径。
- 每行：代码、公司、现价（按显示模式：两位小数，或 ×100 的整数）、涨跌幅（红涨绿跌）、迷你走势、持股、买 / 卖（持仓为 0 时卖按钮禁用）。
- 收盘：抽屉里盖一层本局总资产排行，标出「股神」。
- 手机 / 矮屏（`max-height ≤ 620px`，1280×576 这类横屏手机）：抽屉**从顶栏下面铺到屏幕底部**（`min(520px, 100vw-16px)`
  一条），列表拿回整屏高度；`max-width ≤ 640px` 时铺满宽度、上下贴边。这条原来只在 ≤520px 高时生效，短屏手机上
  抽屉被压在右上角、列表只剩两三行（业主 2026-10-24「手机的商店装备只显示一点点」同一个病根）。

## 实现（为什么能不改引擎的玩法）

| 层 | 用到的表面 | 落点 |
|---|---|---|
| B 服务端 | `server.modules[{ uses:["matchClass"], channels:["trade"] }]` | `server/exchange.mjs`：`registerServer(host)` → `host.matchClass(Base => class extends Base)`，覆写 `startRound / enterPrep / startCombat / finish / handlePackMsg` |
| C 客户端 | `client.panels[{ slot:"screen.game.shopTools", module, styles, messages:["trade","market"] }]` | `ui/exchange.js` + `ui/exchange.css`：`mount(ctx)` 纯 DOM，`ctx.net.on('market')` 收下行、`ctx.net.send('trade')` 下单 |
| 线协议 | 只用引擎已有的 `pack.msg`（C2S/S2C 白名单类型） | 上行 `trade`（`buy` / `sell` / `lever` / `hello`），下行 `market`；**没有新增任何协议类型** |
| 资金 | 引擎唯一写口 `ps.addFunds()`（负数=花钱）；`dirty()` 让资金变化走既有 `m.private` | 不改 `data/*.json`、不改规则 |

安全与失败方向：

- 服务端模块**零 import**，过引擎 import 前的静态扫描（无 `process` / `globalThis` / `require` / `eval` / `new Function`）；
- 所有覆写包 `try/catch`：行情坏了最多「交易所不动」，不会打断对局；
- 面板没有 store、没有对局对象、拿不到 socket 之外的口子，只画与发自己的通道消息 —— 改不了对局结果；
- 数值裁决全在服务端：数量、价格、手续费、持股上限、杠杆额度、利息、爆仓、相位、淘汰，面板发什么都得再过一遍；
- 没装这个包 ⇒ 干净安装一个字节都不变；装了但房间关掉它 ⇒ 走引擎原有的「按房间集合物化」。

## 风险与已知限制

- **平衡是 mod 级的**：分红 + 杠杆会让「攒钱炒股」成为一种可行甚至激进的打法。改了 `LIMITS` / `STOCKS` / `NEWS` 就能调；它不追求官方平衡。
- **波动更大（1.3.0）**：单回合最高 ±45%，3x 满仓遇到熊市块很容易被强平 —— 这是设计意图；想收一点就调 `IDIO_PCT`、市场因子幅度或 `CLAMP_PCT`。
- **杠杆会爆仓**：4x / 5x 满仓遇到一根大阴线，可能被平到只剩零头 —— 这是设计意图，不是 bug；5x 满仓每回合光利息就吃掉约 48% 净资产。
- **显示模式只改屏幕**：无小数点模式下屏幕上的价是真实价的 100 倍（`304` = `3.04` 块）；回执与账本永远按真实两位小数，不存在「按显示价成交」，也不会少付或多收。
- **现金每回合清零**（引擎规则）：所以「持股/还债」才是保值方式，囤现金没有意义。
- **面板位置**：`screen.game.aside` 是右侧固定浮层，抽屉展开时会挡住右侧一部分画面；窄屏变底部抽屉。收起后只剩竖标签。
- **只认官方盟约 id**：六支股票绑的是 `data/bonds.json` 里的 `yanShip` 等；官方改盟约 id 时改 `STOCKS` 表即可。
- **Forge 更新**：本包只依赖 `pack.json` 表面（`client.panels` / `server.modules` / `pack.msg`）。上游若抬 `MOD_API_VERSION` 到 2，本包会被**响亮拒绝**（这正是设计意图），届时按新表面迁移。
