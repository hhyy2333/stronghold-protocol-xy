# 协议源石 ·【特限恢复】· 号角特限模组 · 设计稿（实现口径）

> 日期：2026-10-31。业主原话见 §1。范围：给 **号角**（`char_4039_horn`，本作 5 阶重装·要塞，棋子
> `chess_char_5_08_a` / `_b`）补一张 **ISW-A 特限模组**「号角特限证章」，并把它「在集成战略中…」的专属效果
> 接进【特限恢复】`hex_mode_modules` 那套系统 —— 与已有的 11 名干员（ISW 8 + RA 3）同一口径。

## 0. 已确认事实（业主 2026-10-31 答复）

- **生效口径**：跟随【特限恢复】卡。只有抽到 `hex_mode_modules` 的玩家、且号角**装备并启用了 ISW- 特限模组**时，
  专属效果才在卫戍协议里生效；没有卡 ⇒ 这张模组只给面板（生命/攻击）、特性文本与天赋文本，专属效果不生效。
- **数值**：官方预览图只给「生命 / 攻击 / + / ++」，没有数字，业主授权按官方同类模组量级自拟，全部标 `[ASSUMED]`，
  后续只改数据表 / 卡面即可调。
- **红字落地**：「在集成战略中…」那半能落地的都落地 —— 攻击隐匿敌人、重装干员光环、号角身前 2 格每名友方单位
  的攻击距离 / 远程目标数、3 级部署立即获得技力（有上限）、**可以部署在目标点**（业主 2026-10-31 追加：第二版把
  这条也落地了 —— 保护目标点 `tile_end` 平时不可部署，拥有【特限恢复】且号角装备 ISW- 特限模组时是唯一例外，
  见 §3-5）。

## 1. 业主原文

> 做这个特限模组，号角的。（附图：官方「号角特限证章」模组升级效果前瞻）

- 标题：**号角特限证章** ｜ `//号角` ｜ OPERATOR MODULE UPDATE ｜ RHODES ISLAND

- 01 STAGE：基础数值提升 `生命` `攻击`；天赋【军事要塞】`在场时所有重装干员的攻击力+20%`

## 3. 战斗落地（`server/sim/content/hexcards/stone_mode_modules_isw.js`）

判定与另外 8 名干员完全一致：`u.kind === 'op'`、`u.side === 'ally'`、`u.ownerId` 是卡主、**在场**、`u.def.module`
（或 `def.raw.module`）`type` 以 `ISW-` 开头且 `active === true`，且该干员是 `chess_char_5_08`（`_a` / `_b` 归一）。

逐条：

1. **可以攻击隐匿敌人** —— 号角的攻击（普攻 / 技能覆盖的那一次攻击）**可以选中隐匿的敌人**。
   落地：给号角挂一条 `flags: { seeStealth: true }` 的常驻 buff，`server/sim/targeting.js canTargetEnemy()` 见到
   `attacker.s.flags.seeStealth` 就跳过 `f.stealth && enemyStealthed(e)` 这条排除。
   `[ASSUMED]` 1) 只影响**索敌**：溅射仍按引擎的 `foesInRadius` 跳过隐匿（其它敌人照旧看不见），不额外扩散；
   2) 不改变 `e.hidden`（隐身战场那套「不可见」）—— 那是另一种机制，模组不碰。
2. **在场时额外使重装干员攻击力提升、生命上限提升** —— 号角在场时，**全场己方重装干员**（`profession === 'TANK'`，
   含队友的）额外 `atkPct +8%`、`hpPct +12%`（`[ASSUMED]` 数值；与号角 1 天赋的军事要塞光环**叠加**，不替换）。
   落地：每 0.25 s 刷新一次、持续 0.5 s 的 aura buff（与 `kits/ops/chess_char_5_08-horn.js` 的军事要塞同一手法）。
3. **号角身前 2 格每部署 1 个友方单位 → 攻击距离提升、远程攻击目标数提升** —— 数号角**朝向方向的前 1、前 2 格**
   （`dirVec(u.dir)`）上的己方单位（干员 + 召唤物；装置不算），每有 1 个：`rangeExtend +1`、`maxTargets +1`，
   最多 2 个（两张格子，封顶 +2 / +2）。
   落地：`passiveBuff(u, { rangeExtend: n, maxTargets: n })`，在 `battleStart / deploy / death` 与每 0.5 s 对账一次
   （人走了要掉回去）。`[ASSUMED]` 1) 「身前」按朝向的直线前 2 格，不含左右；2) 「友方单位」= 己方干员与召唤物，
   不算装置与敌人；3) 上限 +2（两张格子各 1 名）。
4. **3 级：自身部署时立即获得 10 点技力（本场最多 20 点）** —— 每次部署（含再部署）`+10`，单个号角本场累计封顶 20。
   落地：`deploy` 钩子 + `u.skill.gainSp(10, …)`（技能忙碌 / 没有技能时不加，交给引擎判）；累计数记在 `u.mem`。
   `[ASSUMED]` 引擎本身还会按 `spCost` 截断，所以实际到手 ≤ 技能消耗；「有上限」按 20 点本场封顶落地。
5. **可以部署在目标点**（业主 2026-10-31 追加要求「可以部署在目标点落地」）—— 卫戍协议的「目标点」= **保护目标点**
   （stage 图例 `tile_end`，棋盘坐标 `(9,2)`；敌人路径的终点、漏怪扣 LP 的格子）。平时它 `buildable NONE`，谁都不能
   站；拥有【特限恢复】且号角装备启用中的 ISW- 特限模组时，它是**唯一例外**。
   落地（服务端 / 客户端 / 不变量共用一份规则 `shared/goalPoint.js`）：
   - `goalPointKeys(stage, field, layout)`：按部署场把 `tile_end` 映射成棋盘坐标（boss 场同样适用）；
   - `canStandOnGoalPoint({ record, ownsModeModules })`：charId 是号角 + 模组启用且 type 以 `ISW` 开头 + 有卡；
   - 服务端 `player/placement.js _legal`（`_mayStandOnGoalPoint`）、`server/match/invariants.js` 与
     `test/match/harness.js` 的棋盘合法性、客户端 `ui/gameLogic/placement.js`（`placementContext.goal` /
     `tileAllows` / `boardTargets` 高亮）都读这一份。
   `[ASSUMED]` 1) 只认号角本人（补位形态是别的角色记录 ⇒ 不适用；自选编队选了号角则适用）；2) 普通形态没有模组
   ⇒ 不适用；3) 目标点**不是阻挡地形**（`grid.blockable` false）：她站在那里不挡路、敌人照常走进去漏掉 —— 模组给的
   是「可以部署」这个位置，不是「可以在目标点拦截」；4) 摆上去以后照常可以换位 / 收回，地形机变与重新计算不会把
   她赶走。
