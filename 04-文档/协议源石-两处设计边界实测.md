# 两处「上游设计边界」实测报告

你报的两个问题我都复现了，而且**在你的 0.3.0 原始仓库里行为完全相同** ——
它们不是移植 bug，是**上游设计本身的边界**。下面是实测数据。

## 问题 1：石像鬼变飞行后隐匿仍在

### 复现（两棵树逐字相同）

```
enemy: enemy_1172_dugago   flying=false
ground + ab:stealth : flying=false  stealthed=true
motion = FLY        : flying=true   stealthed=true     <-- 起飞了，但隐匿没掉
+ ab:flight         : flying=true   stealthed=true     <-- 期望 false
```

### 根因

隐匿脚本（`server/sim/content/hextech.js` `ENEMY_VERB_SCRIPTS.stealth`）只在 `enemySpawn` 那一刻判断一次：

```js
battle.on('enemySpawn', ({ enemy }) => {
  if (enemy.tag === 'boss' || enemy.isBoss || enemy.isFlying) return;   // ← 只在开局判定
  battle.addBuff(enemy, { key: 'ab:stealth', flags: { stealth: true }, ... });
});
```

而 `Unit.isFlying` 是**动态 getter**（读 `flags.levitate / float / groundbind / motion`）：

```js
// server/sim/units.js:210
get isFlying() {
  if (this.side === 'enemy') {
    const f = this.s.flags;
    if (f.levitate) return true;
    if (f.groundbind) return false;
    return this.motion === 'FLY' || !!f.float;
  }
}
```

石像鬼（`enemy_1172_dugago`）的 `statue()` kit 在重生结束时执行 `e.motion = 'FLY'`
（`server/sim/content/enemies/archetypes.js:542`）—— 那一刻 `isFlying` 变成 true，
但 `ab:stealth` buff 已经挂上了，**没有任何代码会摘掉它**。

### 作者的意图（原文注释，`hextech.js:1578`）

> Owner's spec (2026-10-12): only GROUND, non-boss enemies open hidden. **A flyer has no block to end its stealth**
> **and no ground path to hide along**, and a boss opening hidden would hide the stage's main threat behind an
> untargetable frame; both would read as a bug rather than as pressure.

**所以「飞行不该有隐匿」是明确的设计意图**，只是 spawn 时的一次性判断挡不住中途变形。

## 问题 2：镜像协议复制的债务不给干员

### 复现（两棵树逐字相同）

```
after p2 picks 债务:
  p1 hexes : []              p2: [hex_debt]
  p2 watchers: 0

after p1 picks 镜像协议:
  p1 hexes : [hex_mirror, hex_debt]   <-- 复制成功了
  p2 watchers: 0                       <-- 但没建观察者
  p1 funds: 3   p2 funds: 0            <-- +3 落到自己身上（单人分支）
```

### 根因

`applyHexExtras` 用 `depth === 0` 判断（`hextech.js:187`）：

```js
if (spec.debt && depth === 0) {          // ← 镜像复制走的是 depth: 1
  ...
  const mates = m.alivePlayers().filter((p) => p !== ps);
  if (!mates.length) {
    ps.addFunds(funds, { reason: 'hex_debt' });   // 单人：给自己
  } else {
    const to = mates[...];
    to.addFunds(funds, ...);                       // 队友 +3
    to.effects.push({ key: DEBT_EFFECT_KEY, ... }); // 观察者挂在队友身上
  }
}
```

镜像协议的复制走 `resolveMirrorCopies → applyHex(m, picker, copy, { depth: 1 })`，
所以 `depth === 0` 为假 —— **整个债务的 onPick 部分被跳过**（不只是观察者，连 +3 都没走那条分支）。

### 这是设计还是缺陷？

`docs/history/0.3.0.md:109` 只说 depth guard 的目的是**防止同一张卡重复应用**：

> Match-level picks (镜像协议 / 二次抽取) are applied by `applyHexExtras` with a depth guard; EffectRefs carry a
> **stable id (`hex:<id>`)** and are deduplicated, so a hex a player already owns is never applied twice.

而 `test/match/hextech.test.js` 里**没有**任何「镜像复制一张 match-level 卡」的测试 ——
3 条债务测试（647/674/697 行）全部直接 `applyHex(p0, hex_debt)`（depth 0）。

**结论**：两种解释都说得通，只有你能定夺：

| 解释 | 含义 | 需要做什么 |
|---|---|---|
| A. 设计如此 | 镜像只复制 **EffectRef**（那张卡的持续部分），不重放它的 **match-level onPick** | 改文案，说明复制来的债务不会生效 |
| B. 是缺陷 | 复制一张卡就该完整生效 | 把 depth 判断改成「只防自己重复」，让复制也建观察者 |

## 修复（2026-10-15，你确认「两个都修」）

两处都改了，**两棵树同步**（你的 `Stronghold-Protocol-repo` 与改版）。

### 修复 1 · 石像鬼起飞后摘掉隐匿

在 stealth buff 上加一个 0.25 秒的 `onTick`，一旦 `isFlying` 就移除它：

```js
battle.addBuff(enemy, {
  key: 'ab:stealth', flags: { stealth: true }, persist: true, data: { stealthRestore: restore },
  interval: 0.25,
  onTick: ({ battle: b, unit: u }) => { if (u.isFlying) b.removeBuff(u, 'ab:stealth'); },
});
```

**为什么不动 `enemyStealthed`**：官方自带的 `kitStealth`（潜伏者 / 隐形弩手…）用的是**同一个 `ab:stealth`
buff key**，作者明确写了「The gate is scoped to THIS card: the official kits' own 隐匿 keeps hiding」。
所以我只改**这张卡自己加的 buff** —— 官方 kit 的规则一个字没动。
（`findBuff('ab:stealth')` 那道 guard 已保证官方 kit 的敌人不会被这张卡重复加 buff。）

### 修复 2 · 镜像 / 二次抽取 获得债务时完整生效

把 `depth === 0` 改成不看 depth：

```js
-  if (spec.debt && depth === 0) {
+  if (spec.debt) {
```

**为什么安全**：作者在 `hextech.js:161` 写明了 depth guard 的唯一目的 ——

> Both re-enter applyHex with `depth` guard so they **can never chain forever**.

而「永不无限链式」**已由函数顶部的 `depth >= 2` 做到**（它同时限制镜像→镜像、二次抽取→二次抽取）。
`=== 0` 这个额外条件**只**挡住了合法获得。
观察者自身的去重仍在（id 是 `effect:hexdebt:<picker>:<hex>`），重复获得不会叠第二个观察者。

### 验证

```
石像鬼： ground   flying=false stealthed=true
         airborne flying=true  stealthed=false   OK
         对照（地面单位 1 秒后） flying=false stealthed=true   OK

镜像+债务：p1 hexes    : [hex_mirror, hex_debt]
           p2 watchers : 1  [{id: effect:hexdebt:p1:hex_debt, owner: p1}]
           p1 hand     : 0 -> 1   OK

递归安全：镜像→镜像 终止，无 runaway；dispatcher errors 0
```

**测试**（你的仓库，4 个 hextech 套件）：`42 + 73 + 23 + 44 = 182/182` 全通过。

## 附：一个**本来就存在**的行为（两棵树相同，我没有改）

同一张卡通过**测试场重复发放**时会**重复付钱**（0→3→6）。这是 `applyHex` 的既有设计，
`testField.js:75` 写明了：「the same card twice is allowed (`applyHex` dedupes the ref; **the immediate part
runs again**, which is what makes a repeatable test panel work)」。**不是这次修改引入的**，
我保留了它 —— 测试场的可重复性正是靠这个。
