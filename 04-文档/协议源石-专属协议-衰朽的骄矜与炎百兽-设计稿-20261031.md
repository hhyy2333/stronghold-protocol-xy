# 协议源石 · 专属协议【衰朽的骄矜】【炎百兽】· 设计稿（实现口径）

> 日期：2026-10-31。业主原话（逐字照抄，见 §1 / §2）。范围：新增两张**盟约专属协议源石**（2 阶 / gold，`requiresBond`），
> 维多利亚【衰朽的骄矜】与炎【炎百兽】；两张都只在**第 7 回合「盟约专属协议」抽取回合**出现（与【锻炉】同为 2 阶专属）。
> 本稿是实现口径：数值全部写进卡面 `effect` 参数（`tools/hextech/roster.mjs`），战斗模块只读参数，调数不改代码。

## 0. 已确认事实（业主 2026-10-31 答复）

- 两张卡都做成**协议源石卡**（不是新盟约），2 阶（gold），`requiresBond` = 对应核心盟约；只进第 7 回合专属池。
- 「随层数增长」的每层增量（业主口述）：
  - 维多利亚（读【维多利亚】层数 L）：生命 **+10/层**、攻击 **+5/层**、防御 **+3/层**、攻速 **+0.5/层**；
    基准值 = 生命 +50、防御 +50、攻击 +100、攻速 +7（即 `50+10L` / `50+3L` / `100+5L` / `7+0.5L`）。
  - 炎（读【炎】层数 L）：炎佑属性 **+0.4%/层**、每秒回血 **+0.5/层**、祛恶之焰伤害 **+0.2%/层**
    （即 `80+0.4L` % / `20+0.5L` / `60+0.2L` %）。
- 炎百兽「技力消耗 +5%」只作用于**【炎】干员**；「天师炉鼎」按现有装备**【天师古鼎】**（`chess_item_6_03_e_a`）算。
- 「炎佑与对应干员两者生命共享」= **同血池口径**：任一方掉血，两者一起掉同样数值（不是 50/50 分摊）。
- 衰朽的「累计击杀 3 名敌人」只算**该干员自己的击杀**；「首次降至 0」= 每名干员每场只能进一次衰朽。
- 炎百兽召唤的炎佑**叠加**在原【炎】盟约召唤之上（原盟约 6/9 名的炎佑照旧，另按每名【炎】干员各召一只）。

## 1. 卡 A：维多利亚 ·【衰朽的骄矜】`hex_victoria_decay`（2 阶 / gold / requiresBond: victoriaShip）

### 1.1 业主原文

> <在场3名不同〖维多利亚〗干员>
> 携带装备的〖维多利亚〗干员攻击时，无视目标防御法抗。
> 每秒流失0.5%最大生命值。
> <在场5名不同〖维多利亚〗干员>
> 生命值高于80％时，生命＋50防御力＋50攻击力＋100（随层数增长）
> 每秒额外流失0.5%最大生命值，若装备锤子则为0％
> <在场7名不同〖维多利亚〗干员>
> 每秒额外流失1%最大生命值。
> 〖维多利亚〗干员生命值首次降至0时不会撤退，锁血进入「衰朽」，持续8秒：
> · 阻挡数归零， 攻击力＋100％，攻速＋7（随层数增长）；
> · 8秒后若在衰朽期间累计击杀3名敌人，则回复50%生命值并脱离衰朽否则强制撤退。

### 1.2 卡面参数（`effect.victoriaDecay`）

```js
victoriaDecay: {
  equipCount: 3,          // 3 名不同维多利亚：携带装备者攻击无视防御/法抗
  drainPct: 0.5,          // 每秒流失 % 最大生命
  buffCount: 5,           // 5 名不同维多利亚：生命>80% 时的面板加成
  buffHpPct: 80,
  hpFlat: 50, hpPerLayer: 10,
  defFlat: 50, defPerLayer: 3,
  atkFlat: 100, atkPerLayer: 5,
  aspd: 7, aspdPerLayer: 0.5,
  extraDrainPct: 0.5,     // 5 名档的额外流失（装备维式重锤时为 0）
  hammerKeys: ['chess_item_1_01_e', 'chess_item_2_03_e', 'chess_item_3_09_e', 'chess_item_3_10_e', 'chess_item_4_09_e'],
  highCount: 7,           // 7 名不同维多利亚：再额外流失
  highDrainPct: 1,
  decaySec: 8,            // 衰朽持续
  decayKills: 3,          // 衰朽期间击杀数
  decayAtkPct: 100,       // 衰朽期间攻击力 +100%（直接乘算）
  decayAspd: 7, decayAspdPerLayer: 0.5,
  decayHealPct: 50,       // 脱离衰朽回复 50% 最大生命
}
```

### 1.3 实现口径

- **作用域**：拥有该卡的玩家自己的【维多利亚】干员（`isMember(battle, u, 'victoriaShip')` + `u.ownerId === pid`），
  且「在场」= `alive && deployed`（未隐匿也算在场；沿用 `hexHooks.onField` 的 `alive && deployed && !hidden` 口径）。
- **N（不同干员数）**：按场上己方【维多利亚】干员的 `baseChessId` 去重计数（"不同"= 同名干员的普通/精锐只算一个；
  不把【调和】的 +1、变形同构体算进来 —— 那是盟约激活口径，卡面写的是「在场 N 名不同干员」）。`[ASSUMED]`
- **3 名档 · 无视防御法抗**：`hit` 钩子里，来源是「携带 ≥1 件装备的己方【维多利亚】干员」、目标是敌方、
  且这一击不是 元素损伤 / 流失 / 反伤 / 链式附加（`dmg.type === 'element'`、`isHpLoss`、`isRetaliation`、`isChained`）时，
  把 `dmg.defIgnorePct = 1`、`dmg.resIgnorePct = 1`（已经更高的不降）。`[ASSUMED: 只认「攻击」造成的伤害实例；技能/普攻都算]`
- **3 名档 · 每秒流失**：`battle.every(1)`，对每名在场己方【维多利亚】干员 `battle.loseHp(u, u.s.maxHp * drainPct/100,
  { tags: ['hpLoss', 'hex:victoriadecay'] })`。流失可致死（会触发 `fatal` → 衰朽）。
- **5 名档 · 生命 >80% 面板**：对每名在场己方【维多利亚】干员，若 `u.hp > u.s.maxHp * buffHpPct/100`，
  挂常驻 buff `hex:victoriadecay:stat`：`{ hpFlat: 50+10L, defFlat: 50+3L, atkFlat: 100+5L, aspd: 7+0.5L }`；
  条件不满足时移除该 buff。用 `battle.every(0.5)` 复核（层数变化也要跟着刷新），或 `onLayers` + `damaged`/`heal` 复核。
  `[ASSUMED: 生命上限提高后按新的 maxHp 判 80%]`
- **5 名档 · 额外流失**：`extraDrainPct`，但该干员装备任意【维式重锤】（`hammerKeys`，用 `itemKeyOf` 比较）时为 0。
- **7 名档 · 再额外流失**：`highDrainPct`（1%）。
- **衰朽（每名干员每场一次）**：`fatal` 钩子，目标是拥有者的己方【维多利亚】干员且尚未用过衰朽时：
  - `c.prevented = true`；记 `u.mem` 状态（`used`、`until = battle.time + decaySec`、`kills = 0`）；
  - 挂 buff `hex:victoriadecay:decay`：`{ blockCnt: -u.s.blockCnt（进入前的阻挡数，使其归零）, atkPct: 1, aspd: 7+0.5L }`；
  - 窗口内再受致命伤：只 `c.prevented = true`，不重复进入、不延长窗口；
  - `kill` 钩子里 `killer === u && victim.side === 'enemy'` 时 `kills++`；
  - `battle.after(decaySec)` 结算：干员仍活着则移除衰朽 buff；`kills >= decayKills` ⇒ `battle.heal(u, u, u.s.maxHp * decayHealPct/100)`
    （回复 50% 最大生命，脱离衰朽）；否则 `battle.retreat(u, { reason: 'retreat', permanent: true, dying: true })`（强制撤退）。
  - 窗口结束后 `used` 保持 true ⇒ 本场不再进衰朽。

## 2. 卡 B：炎 ·【炎百兽】`hex_yan_beasts`（2 阶 / gold / requiresBond: yanShip）

### 2.1 业主原文

> 技力消耗＋5％。装备天师炉鼎时无视技力消耗增加。
> 战斗开始时召唤对应炎干员的炎佑两者生命共享，该炎佑属性为对应干员的80%（随层数增长）。
> <在场5名不同炎干员>
> 技力消耗额外＋5％
> 炎干员每秒回复20生命（随层数增长）
> 在场7名不同炎干员
> 技力消耗额外＋5％
> 炎佑的祛恶之焰改成锁定2个目标持续施法，最多持续20秒，每秒对目标周围半径1范围内的所有敌方单位造成攻击力60%（随层数增长）的法术伤害。

### 2.2 卡面参数（`effect.yanBeasts`）

```js
yanBeasts: {
  spCostPct: 5,             // 常驻：己方【炎】干员技力消耗 +5%
  spCostTierPct: 5,         // 5 名 / 7 名档各再 +5%
  censerKey: 'chess_item_6_03_e',   // 装备【天师古鼎】的【炎】干员豁免
  summonPct: 80, summonPerLayerPct: 0.4,   // 炎佑属性 = 对应干员的 80% + 0.4%/层（加到模板上）
  regenCount: 5, regen: 20, regenPerLayer: 0.5,   // 5 名档：每秒回血 20 + 0.5/层
  flameCount: 7, flameTargets: 2, flameScale: 60, flameScalePerLayer: 0.2,  // 7 名档：祛恶之焰
}
```

### 2.3 实现口径

- **作用域**：拥有该卡的玩家自己的【炎】干员（`isMember(battle, u, 'yanShip')` + `u.ownerId === pid`）。
  N 的口径同 §1.3（`baseChessId` 去重）。
- **技力消耗**：对每名己方【炎】干员（含之后部署的，挂 `deploy` 钩子）把 `u.skill.spCostMul` 乘上
  `1 + (spCostPct + (N>=5 ? spCostTierPct : 0) + (N>=7 ? spCostTierPct : 0))/100`；装备【天师古鼎】的干员跳过。
  写一次即可（`u.skill.spCostMul` 不会被 `reset()` 还原，参考 batch15b `installOldPower` 的写法；用一个 flag 防重复乘）。
- **战斗开始时召唤**：`battleStart`（优先级 -10，排在【炎】盟约的召唤之后）对**每名**在场己方【炎】干员召唤一只炎佑：
  `spawnYanyou(battle, pid, { atk: op.s.atk * pct, hp: op.s.maxHp * pct, count: 1 })`，`pct = (summonPct + summonPerLayerPct*L)/100`。
  炎佑与对应干员**生命共享（同血池口径）**：任一方受到 HP 伤害时，对另一方 `battle.loseHp(other, amount, { tags: ['hpLoss','hex:yanbeasts:share'] })`；
  带该 tag 的流失不再镜像（防递归）。炎佑模板本身带【禁疗】，`loseHp` 不受影响。`[ASSUMED: 干员阵亡时配对的炎佑一起撤退]`
- **5 名档 · 回血**：对每名在场己方【炎】干员挂常驻 buff `hex:yanbeasts:regen`，`mods: { hpRegen: 20 + 0.5L }`
  （引擎的每秒生命回复属性）；层数变化时刷新（先移除再挂，或 `refresh: 'replace'`）。
- **7 名档 · 祛恶之焰**：对**所有**己方炎佑（原盟约召唤的 + 本卡召唤的）设置运行时覆盖：
  `u.mem.flameTargets = 2`、`u.mem.flameScaleFn = () => (60 + 0.2L) / 100`。
  `server/sim/content/tokens.js` 的 `yanyouKit` 已支持这两个字段（Lead 已改）：
  - `onStart` 锁定 `u.mem.flameTargets`（默认 1）个目标；
  - `onTick` 对每个仍有效的锁定目标各结算一次半径 1 的 AoE，伤害 = `unit.s.atk * (u.mem.flameScaleFn ? u.mem.flameScaleFn() : 数据里的 atk_scale)`。
  - 持续时间沿用数据 `hit_duration`（=20 秒），无需改。
  - 7 名档未达成时不设置覆盖（默认 1 目标 / 数据 60%）。

## 6. 落地补充（2026-10-31 实现时定下的口径）

实现见 `server/sim/content/hexcards/stone_victoria_decay.js`（`installVictoriaDecay`）与
`stone_yan_beasts.js`（`installYanBeasts`）；测试 `test/sim/hex-stone-victoria-decay.test.js`（17 条）、
`test/sim/hex-stone-yan-beasts.test.js`（22 条），接线冒烟 `test/sim/hex-stone-wiring.test.js`。

- **N（在场不同干员数）**：按场上己方成员的 `baseChessId` 去重（同名干员的普通 / 精锐只算一个），
  不把【调和】的 +1、变形同构体算进来。炎百兽的 N 在 `battleStart` 算一次（本场不变）。
- **衰朽的回复**：`battle.heal(u, u, maxHp × 50%)`，走正常治疗（吃禁疗 / 治疗加成）；回复量按结算时的最大生命上限算。
- **衰朽窗口内的再次致命**：只免死（`c.prevented = true`），不重复进入、不延长窗口；本场用过衰朽后正常阵亡。
  若这一发致命已被别的效果（骑士徽章等）免掉，本卡不消耗衰朽。
- **炎佑的生命共享**：对任何 HP 伤害生效（普攻 / 技能 / 反伤 / 流失都算），元素损伤（灌条）不算；
  镜像用 `loseHp`（带 `hex:yanbeasts:share` tag 防递归），同数值、不是 50/50 分摊。
- **炎佑与干员的存亡**：干员阵亡时配对的炎佑一起撤退（`[ASSUMED]`）；炎佑先死不会带走干员。
- **5 名 / 7 名档的阈值**：炎百兽直接读卡面 `regenCount` / `flameCount`（不另造参数）。
- **7 名档的祛恶之焰**：所有己方炎佑（原【炎】盟约召唤的 + 本卡召唤的）都设 `mem.flameTargets` /
  `mem.flameScaleFn`；未达 7 名档时不设，保持数据里的 1 目标 / 60%。
