## 三、修掉的三个真问题

### 1. `data/assets.json` 丢了 `voiceJpChars`（真回归）

`tools/fetch-assets.mjs:333` 明确生成 `voiceJpChars`，HEAD 版本里也有：

```
HEAD:     …"voiceChars":192,"voiceJpChars":192}
工作树:   …"voiceChars":192}              ← 被 0.2.5 合并吃掉了
```

两个独立测试都在断言它：`test/docs-consistency.test.js:920`、`test/feedback7-voices.test.js:71`。
因为是 JSON 单行文本被整份覆盖，这个字段在合并时静默丢失了。

**已修**：补回 `"voiceJpChars":192`。`hash` 只覆盖 `body`（不含 `stats`），所以补 `stats` 不会让 hash 失效
（`contentHash` 在 `tools/assets/manifest.mjs:167`，对 `body` 取值）。

### 2. 两条测试断言还钉在 0.2.5 之前的旧行为上

上游 0.2.5 的 **#479 / PR #504** 有意改了规则：漏怪时顶栏**不再**立即显示扣除后的数值，而是
「保留当前数值 + 红字 −N 标记待扣」，**结算时才扣**。代码（`public/js/ui/hud.js` 的 `liveLp`/`pending`）、
`README.md`、`docs/PLAYING.md`、`CHANGELOG.md` 都已经按新行为写好了，**只有测试没跟上**：

- `test/docs-consistency.test.js:293` 要求 PLAYING 里写「会**立即**显示扣除后的数值」
- `test/docs-consistency.test.js:294` 要求 README 里写「目标生命值实时减少」

这两句在合并时被有意改掉了（`git diff` 可见），于是测试永远红。

**已修**：把这两条改成断言**现行**行为（先不变 + −N + 结算才扣），并加注释说明是 #479 的有意改动。

### 3. `docs/history/0.3.0.md` 里 `### 29.17` 出现了两次

「房间一览」那条被编号成 `29.17`，但下面「第五批：四张战斗卡改造」也是 `29.17`。
而交叉引用是按号走的：`docs/BALANCE.md:486` 把「第五批」叫作 §29.17，`docs/META.md:197` 把动词卡叫作 §29.18。

所以**不能**把「第五批」改成 29.18（会撞上现有的 29.18 动词卡，我试过，确实撞了）。
正确做法是：房间一览本来就是 **§30** 的内容（正文自己就写着「规则与协议全文见 **§30**」），
不该占用 §29 的号。

**已修**：改成 `### 房间一览 / 在线人数 / 多人匹配（§30，2026-10-11 追加）`，不再携带 §29 编号。
