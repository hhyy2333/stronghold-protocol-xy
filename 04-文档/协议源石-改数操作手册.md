# 协议源石 · 改数操作手册

> 面向：要调协议源石数值的人。目标：**把一次改数从「查好大一会」压到 1–2 分钟**。
> 本文所有命令、数字、输出格式都来自 2026-10-13 在本机的**实测**，不是凭印象写的。
> 规则出处：`docs/history/0.3.0.md` §29（现行规则的完整修订史）+ `docs/BALANCE.md` §8（数值与设计取向）。

## 〇、先记住这一张表（下面全部细节都可以回来查）

| 你要改什么 | 只改这一个地方 |
|---|---|
| 卡的数值 / 效果 / 稀有度 / 名字 / 描述 | `tools/hextech/roster.mjs` |
| 抽取时机、每人几张、刷新几次、敌方怎么给 | `tools/hextech/roster.mjs` 的 `FORMAT`（同文件顶部） |
| 三档稀有度的权重与阶位图编号 | `tools/hextech/roster.mjs` 的 `RARITIES` |

改名单只改 `roster.mjs`，然后重新生成。

## 一、最小循环：改一个数字（30 秒）

以「盟约回响：每回合所有已激活盟约 +5 层 → +3 层」为例。

### 第 1 步：找到那张卡

```powershell
cd C:\Users\hhyyl\Downloads\Stronghold-Protocol-v0.2.1\Stronghold-Protocol-repo
Select-String -Path tools/hextech/roster.mjs -Pattern "hex_echo" -Context 0,8
```

输出就是这张卡的全部字段：

```js
{
  id: 'hex_echo',
  name: '盟约回响',
  desc: '每回合开始时，所有已激活盟约 +5 层。',
  rarity: 'silver',
  effect: { onRoundStart: { allActiveLayers: 5 } },
},
```

**技巧**：不知道 id 就按中文名搜——`Select-String -Path tools/hextech/roster.mjs -Pattern '盟约回响'`。

### 第 2 步：改数字（**数值和描述都要改**）

```js
effect: { onRoundStart: { allActiveLayers: 3 } },
desc: '每回合开始时，所有已激活盟约 +3 层。',
```

### 第 3 步：生成 + 自检

```powershell
node tools/build-hextech.mjs            # 写入 data/hextech.json
node tools/build-hextech.mjs --check    # 应输出 "is up to date"
```

### 第 4 步：跑内容测试

```powershell
node test/content/hextech.test.js       # 0.6 秒
```

## 二、**最关键的一节**：改完之后，到底要跑哪些测试？

这是「查好大一会」的真正来源。实测（把 `allActiveLayers` 5 改成 3 之后）：

| 套件 | 结果 | 耗时 | 说明 |
|---|---|---|---|
| `test/content/hextech.test.js` | **通过** | 0.6s | 只校验名单结构、不校验具体数值 |
| `test/match/hextech.test.js` | **通过** | 0.9s | 对局侧流程 |
| `test/sim/hextech-battle.test.js` | **通过** | — | 战斗被动 |
| `test/ui/hextechDraft.test.js` | **通过** | — | 抽卡界面 |
| **`test/golden.test.js`** | **失败 1** | 3s（快速子集） | **数值真的变了，只有它抓得住** |

> **结论**：改了数值，前四个**都不会红**，只有 **golden** 会红。
> 所以如果你的改动只碰了数值，**直接跑 golden 就行**，不用把五个都跑一遍。

## 三、golden 红了怎么办（从 70 秒压到 4 秒）

### 3.1 先看它说了什么

`test/golden.test.js` 失败时会**指名道姓**地打印场景与字段（实测输出格式）：

```
golden matches: 1 scenario(s) differ
  solo-FUNNY-1:
    .end.teamLp: 27 → 26
```

**读懂它**：

- `golden matches` —— 哪个家族（`roster` / `bonds` / `fields` / `matches` / `standins` / `diy`）
- `solo-FUNNY-1` —— 哪个场景（`matches` 家族是「一局完整对局」，id 形如 `solo-FUNNY-1`、`coop-4-NORMAL-2`）
- `.end.teamLp: 27 → 26` —— **具体哪个字段、旧值 → 新值**

> ⚠ 直接用 `node test/golden.test.js` 看即可。**不要**用 `| Select-String "differ"` 之类过滤，
> 会把上面那段最有用的明细滤掉（我一开始就是这么漏看的）。

### 3.2 确认这个变化是不是你要的

- **是**：进 §3.3。
- **不是**：你的改动有意料之外的副作用（比如你以为只动了 A，结果 B 也变了）——先查清楚再继续。

### 3.3 只重跑一个场景（省时间的关键）

```powershell
# 全量：约 70 秒
node tools/golden.mjs

# 只跑一个家族 + 快速子集：约 25 秒
node tools/golden.mjs --family matches --fast

# 只跑一个场景：约 4 秒   ⭐
node tools/golden.mjs --family matches --only solo-FUNNY-1

# 先列出所有场景 id，挑你要的
node tools/golden.mjs --list
```

实测耗时（本机 4 worker）：**全量 67–70s → 单家族 25s → 单场景 4.2s**。

### 3.4 正式更新并复核

```powershell
npm run golden:update      # 约 67 秒，会重写 6 个 golden 文件
node test/golden.test.js   # 应 9/9 全绿
```

**然后 `git diff test/golden/` 人工看一遍**，确认只有你预期的场景变了。
这一步不是形式——`AGENTS.md` 硬性要求「有意改玩法时同批更新 golden，并在提交信息里点名移动了哪些场景、为什么」。

## 四、⚠ 三条会烧掉你半天的坑（我踩过）

### 坑 1：**绝对不要**用 `git checkout` 撤销你在 `roster.mjs` 上的改动

`git checkout -- tools/hextech/roster.mjs` 会把它还原成**上一次提交**的版本。
如果另一个人（或另一次工作）在 `roster.mjs` 上有**未提交**的改动，**那些改动会当场消失，git 也找不回来**
（未 `git add` 的工作树改动不在 git 的对象库里，`git fsck` 捞不到）。

> 我在写这份手册时就踩了：`git checkout` 把 66 张卡打回 51 张。
> 靠 `_bk/roster.mjs` 备份（10-12 20:03 的快照）才恢复，恢复后与备份**逐字节一致**。

**正确做法**：改之前自己留一份。

```powershell
Copy-Item tools/hextech/roster.mjs "$env:TEMP\roster.bak"
# 撤销时
Copy-Item "$env:TEMP\roster.bak" tools/hextech/roster.mjs -Force
node tools/build-hextech.mjs
```

### 坑 2：`Set-Content -NoNewline` 在本机 **pwsh 7 上不存在**

想用 PowerShell 批量替换 roster 里的数字时，`-NoNewline` 会报
「找不到与参数名称 'NoNewline' 匹配的参数」，而 `Set-Content` **已经截断了文件** —— 文件就毁了。

**正确做法**：用 node 改，或改完立刻 `node -e "import('./tools/hextech/roster.mjs')"` 验证它还能加载。

### 坑 3：改了 `desc` 中文，**英文翻译会静默失效**

英文包用**中文原文当 msgid**（`docs/I18N.md`）。实测：

```
desc = '每回合开始时，所有已激活盟约 +5 层。'
en.json 里有这条 → 'At the start of every round, every active bond gains 5 layers.'
```

你把 `+5` 改成 `+3`，msgid 就变成 `…+3 层。`，**en.json 里没有这条 → 英文客户端回退显示中文。**

**所以改描述要同步改 `public/i18n/en.json` 的键**（改完跑 `node tools/i18n.mjs check --all --strict` 复查）。
只改数值、不改描述，就没这个问题。

## 五、按「改什么」查手册

### 5.1 改一张卡的数值

见 §一。**数值和 `desc` 一起改**，然后 golden。

### 5.2 加一张新卡

在 `PLAYER_HEXES`（或 `ENEMY_HEXES`）数组里加一项：

```js
{
  id: 'hex_你的id',            // 必须 ^[a-z][a-z0-9_]*$，全局唯一
  name: '中文名',
  desc: '中文描述。',
  rarity: 'silver',            // silver | gold | prismatic（= 1/2/3 阶）
  effect: { onPick: { funds: 2 } },
},
```

`node tools/build-hextech.mjs` 会替你校验：id 格式、重复 id、稀有度是否存在、name/desc 是否齐全、
`chess.tier` 是否是 1–6 或 `'level'`、`item.pool`/`item.tier`、`goldenItem.tier`、敌方 `mods` 的键与取值范围（`0.5 < v ≤ 1.35`）、
`countAdd` 是否 1–3、`payout.perLeak` 是否 1–9、稀有度权重是否和为 1、阶位是否唯一且与名字（`1阶`/`2阶`/`3阶`）对得上。

**它抓不到的**：`effect` 里的 spec 键写错（会被运行时静默忽略）——所以要跑 golden 看它到底有没有生效。
卡数变化后 `test/content/hextech.test.js` 的计数断言也会红，记得一起改。

### 5.3 改抽取时机 / 张数

`FORMAT`（roster.mjs 顶部）：

```js
export const FORMAT = {
  rounds: [1, 6, 11],   // 哪几回合抽
  offer: 3,             // 每人几张可选
  rerolls: 1,           // 每人几次刷新
  timerSec: 30,         // 计时秒数（单人/独立模拟不计时）
  timeout: 'random',    // 超时怎么办
  enemyPerDraw: 1,      // 每次抽完敌方得几张
  enemyPersist: 'match',// 敌方累计到对局结束
};
```

⚠ `offer` 改了要注意：协议层有个 `HEX_MAX_OFFER`（`shared/hextech.js`，值 6）在挡 `g.hex {idx}` 的上界。

### 5.4 改稀有度权重

```js
export const RARITIES = [
  { id: 'silver', name: '1阶', weight: 0.60, tier: 1 },
  { id: 'gold', name: '2阶', weight: 0.30, tier: 2 },
  { id: 'prismatic', name: '3阶', weight: 0.10, tier: 3 },
];
```

三个 `weight` 必须**和恰好为 1**（`build-hextech` 会断言）；`tier` 必须唯一且与 `name` 的 `N阶` 一致——
它决定卡面用哪张阶位图（`hextech/tier/<tier>.png`）。

⚠ **改权重也会动 golden**（我原以为不会，实测打脸）。把 `0.60/0.30/0.10` 改成 `0.70/0.20/0.10` 后，单个场景的输出是：

```
    .rng.meta: 1 → 10
    … 32 more
MISMATCH · 3611 ms
```

原因是权重参与抽取，**改变了 RNG 消耗序列**，于是整局后续的随机都被推移——`.rng.meta` 只是最先被打印的那一项。
所以**任何 `roster.mjs` 的改动（数值、权重、卡序）都要走一遍 golden**，没有"只影响手感不影响结果"的捷径。
（实测于 2026-10-13；恢复后与备份逐字节一致。）

### 5.5 改**效果的算法本身**（不只是参数）

改参数不够用时才动引擎，两处：

- `server/sim/content/hextech.js` 的 `applySpec` —— 一个新 spec 键怎么算（战斗内/预备期效果）
- `server/sim/content/hextech.js` 的 `install` —— 装进战斗的被动与脚本

**这是重活**：它改变真实行为，golden 会大面积移动，而且**必须**同步 `docs/history/0.3.0.md` §29 与相关文档
（`test/docs-consistency.test.js` 会校验文档与代码说的一致）。

## 七、给接手者的三条经验

1. **`roster.mjs` 是唯一手写来源，别的手改都是错**。`data/hextech.json` 是生成物。
2. **数值改动的门禁只有 golden**；结构门禁是 `test/content/hextech.test.js`。改数值时别再挨个跑五个套件。
3. **`git checkout` 是危险动作**——本工作区长期有别人未提交的改动。撤自己的改动请用自己留的备份。

> 数值取向（哪张卡该多强、上下界、已知的重复卡）见 `docs/BALANCE.md` §8；
> 每张卡的来历与逐次调整见 `docs/history/0.3.0.md` §29.2 / §29.7 / §29.9 / §29.19 / §29.20 / §29.22 / §29.23 / §29.27。
