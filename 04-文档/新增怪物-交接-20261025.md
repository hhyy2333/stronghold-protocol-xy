# 新增怪物（fork 自加敌人）— 交接说明

写于 2026-10-25，对应 `0.19.25` 之后的仓库状态。**接手前先读完第 5 节「素材管线」**——这条线上出过的三次线上事故，全部是那一节里的 git-ignored 陷阱造成的，不是逻辑写错。

---

## 1. 一句话现状

官方 300 个敌人之外，fork 自己加了 **49 个能进波次的敌人**（4 批），另有 **9 张「强怪悬赏」卡**把它们送进 R9 悬赏决策；这 49 个的 Spine 模型全部从**本机《明日方舟》客户端**抽出，共 **52 个模型目录**（49 个进波次 + 3 个只进图鉴 / 已撤下）。

| 数 | 值 | 从哪看 |
|---|---|---|
| 进波次的 fork 敌人 | **49** | `docs/research/16-extra-enemies.json` 的 `batches[].enemies` 展平 |
| 有声明的本地模型（`spineLocal`） | **52** | `data/assets.json` → `enemies[*].spineLocal` |
| 本地模型的资源分组 | **52** | `data/local-assets.json` → `groups['spine/enemy/<key>']` |

> 52 − 49 = 3：`enemy_1305_mhslim` / `enemy_1305_mhslim_2`（灼热 / 炽焰源石虫，走悬赏与波次之外的池）与 `enemy_10109_mjcgst`（沃尔夫之影，**已按业主要求撤下**，模型还留在盘上但 key 不进池、也没有 kit）。

## 2. 选人的四条硬条件

这不是「随便找个没收录的怪」，四条缺一不可（写在 `16-extra-enemies.json` 的 `_meta.notes`）：

1. **未收录、NORMAL/ELITE、`applyWay ≠ NONE`、非 `notCountInTotal`、地面（`motion ≠ FLY`）**；
2. **零技能零天赋** —— 通用 AI 就能正确表达，不需要写 kit（第一批就是这么选的 21 个）；
3. **无同族已收录** —— 否则只是换个皮，不是「新面孔」；
4. **模型在客户端里真的有** —— 注意 `enemy_1037_lunsbr` 的骨架实际叫 `enemy_1037_lunsabr`，另有两个整个不存在；第一批 24 个候选因此只落地 21 个。

第二、三、四批放宽了第 2 条（带机制），但换成更严的一条：**机制必须能用引擎已有的原语表达**。带结晶 / 装备 / 狂欢时刻 / 摄影区域 / 月光 / 沙尘暴这类本模式没有的系统的敌人一律不做，避免半残机制上线。

强度带按占位符 `attrPower` 定：NORMAL 占位 `enemy_1422_lrsldr` P=6620、ELITE 占位 `enemy_1427_lrnazg` P=21150；本批取 NORMAL P 1700–6000、ELITE P 8700–26000。

## 5. 素材管线（这条线上所有的坑都在这里）

### 5.1 三段式

```
① 抽模型   tools/local-extract/extract.py            → public/assets/local/spine/enemy/<key>/*.skel|.atlas|.png
                                                       （git-ignored，约 270 MB 的一部分）
② 建分组   node tools/fetch-assets.mjs --local-spines → data/assets.json 的 enemies[<key>].spineLocal（含 .group）
                                                       data/local-assets.json 的 groups['spine/enemy/<key>']
                                                       （两个都 git-ignored）
③ 打包     node 05-部署/pack-0192x.mjs               → 把 ② 写的两份清单 + ① 的模型目录一起塞进 tar
```

### 5.2 三个必须记住的事实

1. **`spineLocal.group` 不在仓库里**。`data/assets.json` 是被 git 跟踪的，但 `group` 这一格由 `fetch-assets.mjs --local-spines` **现场写入**，写出来的文件又被 `.gitignore` 排掉 —— 也就是说**从 git 干净 clone 出来的仓库天生缺这一格**。2026-10-25 业主报「有人新增敌人的素材没加载出来」，根因就是它：52 个全空 ⇒ 客户端一个都找不到模型。修法就是重跑 ②（语义 diff 是 52 增 / 0 删 / 0 改，只补 `group`）。
2. **模型目录不在仓库里**。`public/assets/local/**` 是 `.gitignore` 的，**永远不能指望 `git archive HEAD` 把它带进发布包**。打包脚本必须显式地把模型目录 cp 进去。
3. **打包不能靠「仓库里有什么」**。这三份东西都不在 git 里，所以打包脚本的做法是「从 `.git` 读 HEAD 出代码 + 从工作区补本机产物」，并且**每一样本机产物都要有硬闸**（缺了就拒绝出包，不给出半成品）。

### 5.3 `--local-spines` 的两半

- `data/assets.json` 的 `enemies[*].spineLocal`：`skel` / `atlas` / `textures` / `pma` / `anims` / `bounds` / **`group`**；
- `data/local-assets.json` 的 `groups['spine/enemy/<key>']`：把每个文件名映射到 `/assets/~<hash>/local/...` 的**内容哈希 URL**（`server/http/assetViews.js` 重写，按组算一个 hash）。

客户端解析链是 **`spineLocal.group` → `local-assets.json` 里同名分组 → 实际文件**，三环断一环就是「刷出来但画面是空的」。打包脚本里那个「全部 52 个可解析」的闸门就是在逐环验证这条链。

### 5.4 相关的三个工具

| 工具 | 作用 |
|---|---|
| `tools/local-extract/extract.py` | 从本机客户端抽模型。`ENEMY_SPINES` 开头是 2 个（灼热 / 炽焰源石虫），2026-10-23 起继续往后加 |
| `tools/local-extract/rebuild-enemy-groups.mjs` | 只重建分组（当 `local-assets.json` 被别的工具重写、`group` 对不上时用）|
| `tools/fetch-assets.mjs --local-spines` | 正路：把抽出来的模型重新写进两份清单 |

### 5.5 为什么不用社区 dump

社区 dump 只有 245 个敌人模型，除 3 个外全都已收录；剩下 1322 个未收录的里只有 49 个能借到同族模型 —— **真正的新面孔只能从本地客户端抽**。这是整条线必须依赖「本机装了《明日方舟》客户端」的原因。

| 位置 | 作用 |
|---|---|

| `server/sim/content/enemies/forkwave.js` | 带机制那批的 kit（只用引擎原语：`deathBoom` / `splashAttack` / `blockWeight` / `stealth` / `unblockable` / `enemyAura` / `skill`）|
| `data/enemies.json` / `data/factions.json` | 生成物，**绝不手改**，改 `build-data.mjs` 后重跑 |
| `data/assets.json`（`spineLocal`）| 模型声明；`group` 由 5.2 的 ② 写 |
| `05-部署/pack-0192x.mjs` | 打包 + 三道敌人相关硬闸 |

### 挂载规则（`attachWaveEnemies`，改动前必读）

- 官方 key **恒在**每池的 `[0]`，fork key 追加在后面；
- 同类（`isFlyEnemy`）、同档（`rank`）、强度带 **[0.85, 1.25]** 相对该池锚点；
- **每池最多 1 个 fork key**（官方仍占约 63 % 的槽位）；
- `share < 1` 的 key 按哈希抽签只占该池位的 1/4（业主「凶豕兽作战里少放点，冰晶射手作战里少放点」）。

改带宽 / 改每池数量 = 直接改「每回合人数相对官方分布」的偏差。当前实测 **8.2 %**（20 局 × 13 回合），FLY 回合占比 9.9 %（官方约 10 %），21 个里 20 个会真的刷出来。

## 8. 再加一个新怪，按这个顺序

1. 在 `16-extra-enemies.json` 加一条（`key` / `rank` / `name` / `hp` / `atk` / `def` / `res` / `attrPower` / `why`；要降占比就加 `share`）；带机制的再加进合适的批次并写 `forkwave.js` 的 kit。
2. `tools/local-extract/extract.py` 的 `ENEMY_SPINES` 加这个 key → 跑抽取（需要本机客户端）。
3. `node tools/fetch-assets.mjs --local-spines` → 写 `data/assets.json` 的 `spineLocal` 与 `data/local-assets.json` 的分组。
4. `node tools/build-data.mjs` → 重生成 `data/enemies.json` / `factions.json` / `choices.json` 等（**不要手改这些文件**）。
5. 跑测试：`node test/data.test.js`（本机 checkout 缺 `tools/custom-ops.mjs`，这条**本来就跑不了**，见第 9 节）、`node test/content/hextech.test.js`、`node test/sim/detmath.test.js`。
6. 打包（第 7 节）→ **确认三道闸门全过**。
7. 部署后必须验证：拿一个具体 key 的 `.skel` / `.atlas` 直连一次 HTTP **200**，并且 `/healthz?traffic=1` 的 `assetHashes.views` 里三份清单齐全（`assets.json` / `local-assets.json` / `local-fx.json`）。

## 9. 已知缺口 / 别踩

- **`enemy_1018_aoemag` 挂不上波次**（见第 3 节）。放开带宽能挂上，但人数偏差会翻倍到约 14 %。业主口径问题，等指示。
- **沃尔夫之影（`enemy_10109_mjcgst`）已撤下**：没有月光时它会是「隐匿 + 不可阻挡 + 不攻击」，走一路没人拦得住也没人打得着。模型还在本机，key 不进池、没有 kit。想恢复要先把月光系统做出来。
- **本机 checkout 缺 `tools/custom-ops.mjs`**（git 里从来没有这个文件），`test/data.test.js` / `backups.test.js` / 几个 kits 测试**在 import 阶段就失败**。这不是本次改动引入的，但意味着「数据完整性测试」在这台机器上跑不了 —— 加怪物时更要手动核对第 7 节的闸门。
- **`test/golden/` 整个目录不在本 checkout 里**，`npm run golden` 跑不了，所以「goldens 未移动」这条规矩本机无法自证。`test/golden/` 不在 git 里这件事本身也值得查一下是不是有意为之。
- 华为云那台没发（本机无 SSH 凭证），线上只有 47.122.107.213 这一台。
