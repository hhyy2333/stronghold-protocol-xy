# 工坊包数据层移植评估（只带数据、不执行第三方代码）

> 评估对象：`参考对象\Stronghold-Protocol-Forge-0.15.0-0.2.4-win-x64` 的「创意工坊包」系统。
> 移植目标树：`Stronghold-Protocol-repo`（业主 0.3.0 分支，git HEAD = v0.2.3 merge，底座是上游 v0.2.4）。
> 本文只做评估与方案，不含任何代码改动。行号与文件路径均已核对到具体位置。

---

## 0. 结论

1. **值得做，但不该照搬 Forge 的 `workshop/` 系统。** Forge 的工坊是一整套平行设施（独立目录、独立注册表、`modCatalog`、客户端 `sync/align`、房间按摘要物化 `roomAssets`）。我们树里**已经有等价的两块地基**：
   - 内容包机制（`packs/` + `shared/packs.js` 的类型表 + `server/packs.js` 注册表 + `GET /packs/index.json` / `GET /packs/<id>/<file>` 白名单服务）；
   - 房间级内容开关 + 服务端权威数据过滤（`shared/mods.js` `filterData` + `server/lobby.js:1529 dataFor(room)` + 客户端 `public/js/data.js:308-323`）。
   而我们自己的文档已经把路铺好了：`docs/PACKS.md:112` 写着 `data` 类型（planned，服务端启动时应用的数据补丁），`:117-121` 写着「做 data 包之前，内容 mod 是简化前置……**它的 `filterData` 就是 data 包载荷会被应用的位置**，房间开关与客户端过滤可以直接沿用」。
2. **所以移植物是 Forge 的「数据规则」，不是它的设施**：内容文件规范化 + 只增不改 + `overrides` 显式白名单 + 顶层键闭集拒绝 + 记录自检 + 摘要身份。执行面（`kits/*.js`、`server.meta/modules/battle/room`、`client.panels`、`routes`、`assets` 容器、`voices/skins/forms/fx`）**一格都不搬**。
3. **必须在 P1 就解决的一致性硬点**：我们的浏览器**直接静态取 `data/*.json`**（`server/http/static.js:61` 挂 `/data/`；`tools/package.mjs:250` 把 `/data/` 映射到 `data/`），而服务端是在内存里叠加/过滤（`server/data.js:81` 冻结、`server/lobby.js:1529` 按房间过滤）。**服务端内存里的包内容不会自动到达浏览器**，所以「只做服务端」不成立。Forge 的解法最省事，照抄即可：**把合并后的正文由服务端在内存里产出、并先于磁盘挂载地应答**（`server/http/workshop.js:buildWorkshopDataFiles` + `server/workshop.js:999 workshopTouchedFiles`，`static.js:255-265` 带 `Cache-Control: no-cache` 与 `ETag: "ws-<sha1(body)[:20]>"`）⇒ **浏览器零改动**。注意 ETag 只是缓存校验、**不是**完整性判据，所以 `docs/PACKS.md:141-142` 要求的内容哈希握手仍然要做。
4. 规模：P1 约 **1,300–1,900 行**改动/新增（其中共享规则模块 600–900 行，其余是类型表、注册表、数据管线 seam、合并正文路由、工具、测试、文档），P2（房间子集 + 准备前对齐）再加 **400–800 行**。不引入任何新依赖。

## 2. 目标 / 非目标

### 目标（P1 + P2）
- `data` 类型成为 **supported**：`packs/<id>/pack.json` + 它点名的数据文件 → 启动时校验并叠加进服务端内存数据；浏览器取同一批文件、用同一份代码本地合并 → **两端数据逐字节同源**。
- 只增不改：官方记录要改必须写 `overrides`；非法/未知/冲突项**点名报告且不生效**，绝不静默。
- 每个已装包可作为**房间级开关**（复用现有 mod 开关），房间关掉它时，它的记录从该房间的数据里消失。
- 内容哈希进握手（`welcome` / `/healthz` / BattleSpec + UI 标记），客户端在「准备」前核对本地包字节。
- 工具与文档：`tools/packs.mjs list/check` 对 data 类型给出与装载器**同一套**判据；`docs/PACKS.md` §4 改成 supported 并写清角色、字段、检查、规则。

### 非目标（明确不做，且理由进文档）
- **任何执行第三方代码的格子**：`kits/*.js`、`server.meta`、`server.modules`、`server.battle`、`server.room`、`client.panels`、`routes`、`assets` 容器、`forms`/`fx` 渲染增量。
- **素材类型**（`assets` 保持 planned）：包不能带立绘/语音（`voices`/`voiceLangs`）/时装（`skins`）/图标映射（`bondIcons`/`itemIcons`/`art`）。⇒ P1 的 data 包只能带**规则与数据**；新增干员没有立绘（退化表现照旧由客户端处理）。
- Forge 的 ABI 概念（`api` / `MOD_API_VERSION`）：**没有代码就没有 ABI**；我们只保留已有的 `app` 版本区间（`docs/PACKS.md:62`）。
- 不新建第二套发现/索引/下载系统：`/packs/index.json` + `/packs/<id>/<file>` 就是我们的 `modCatalog` + 下载通道。
- 包不写 `data/*.json`；包不进 golden；本机第三方包不进发布包。

## 3. 设计

### 3.1 数据流

```
服务端（启动一次，live:false）
  server/packs.js 扫 packs/  →  对每个 type=data 的包：
      读 pack.json → normalizeManifest(新 data 分支)      [shared/packs.js]
      读它点名的每个数据文件 → normalizeDataFile(...)     [shared/dataPacks.js]
      冲突/非法项 → report（点名 + 理由），坏的整条/整包不生效
      digest = modManifestDigest(声明文件排序后的 {path,hash})   [shared/modIdentity 的同构实现]
  server/data.js loadData():  deepFreeze 之前 applyDataPacks(out, packs) → out
      日志：[packs] applied N data pack(s): … （+ 每条 error/warning）
  server/lobby.js dataFor(room):  filterData(base, room.mods)   ← 已有
      （P2：包按 id 注册成 mod；关掉的包其记录从该房间数据里摘除）

浏览器（P1：零改动）
  取 /data/<file>.json —— 由服务端【合并后的正文】应答（Forge 同款分支，先于磁盘挂载）
      浏览器不需要知道包的存在，拿到什么就是什么
  filterData(..., room.mods)          ← 已有（public/js/data.js:308-323）
  P2：准备前核对 welcome 里的内容摘要   ← 对齐语义照抄 Forge public/js/mods/align.js:94-114
```

### 3.3 角色（`files`）的提议名单

对齐我们的 `server/data.js:27-31 DATA_FILES`，**去掉 `config`（规则，Forge 同样刻意排除）**、**去掉 `assets`（美术清单 → 属于未来的 assets 类型）**、**加上 `hextech`（0.3.0 自有内容）**：

```
chess  bonds  garrisons  items  bands  effects  choices  enemies  factions
```

### P3（可选，非承诺）—— 包的导入/导出与脚手架
zip 能力**我们其实已经有**，只是没被当公用件用：
- **读**：`tools/package-update.mjs:62 export function readZip(zipPath, onFile)` —— 纯 Node，覆盖 stored/deflate（`zlib.inflateRawSync`）、zip64、UTF-8 名、Info-ZIP 0x7075 Unicode Path extra field（名字 CRC 校验）、CRC 校验、拒软链（`:117`），注释里写明它服务的是「GitHub 与 `tools/package.mjs` 给出的那种 zip」。⇒ **包导入**几乎免费，只需把它提成 `tools/zip.mjs`（或直接 import）再加「解到临时目录 → 校验清单 → 搬进 `packs/<id>/`」的流程。

建议顺序：先只做**导入**（用现有 `readZip`）+ 目录形态分发；导出留到有人真的要分享包时再做。

## 6. 需要业主拍板的四件事

1. **第三方包要不要提交进 git？** 我们的 `packs/` 是「提交才随发布包走」（`docs/PACKS.md:161-163`）。Forge 的工坊包是**本机目录**、不进仓库。建议：`packs/<id>/` 里只提交我们认可的包；第三方包默认 `.gitignore`（或放一个不打包的目录），与现机制一致。
2. **内容哈希什么时候上？** 我们自己的文档要求「data 包上线**之前**」就有（`docs/PACKS.md:141-142`）。建议 P1 就做（摘要 + `welcome` + UI 标记），否则等于带着一个已知的一致性缺口上线。
3. **素材（`assets` 类型）要不要跟着做？** 不做的话 data 包只能带规则、不能带立绘/图标（新干员会是「无立绘」的退化表现）。做的话是**另一套类型**（只读文件 + 清单，仍然不执行代码），工作量与风险都要单独评估。
4. **房间子集（P2）是否必要？** 若只想要「服务器整体加装内容」，P1 就够；但那样就退回到 Forge 的「本体含全部已装包」，与我们 `docs/MODS.md` 的「房间级开关」哲学不完全一致。

## 7. 风险与坑

| 风险 | 说明与对策 |
| --- | --- |
| **两端数据同源** | 最大的一条：浏览器静态取 `/data/`，服务端内存叠加。解法照抄 Forge——**服务端产出合并正文、先于磁盘挂载地应答**（浏览器零改动）。注意 ETag ≠ 完整性，摘要握手仍要做 |
| 确定性/顺序 | 包的叠加顺序必须固定（建议：包 id 字典序；同一文件内记录按 id 排序），否则两端摘要与推演会漂移 |
| golden | 包的装载默认必须是「关」：`loadData({packsDir: null})` 等价于今天；golden 只跑原生内容（我们 doc 的硬要求） |
| 打包/更新 | `tools/package.mjs` 的 `URL_MOUNTS` 已含 `/packs/`，但**只带已提交包**；第三方包若被误提交会进入所有客户端（Forge 的等价教训见 `docs/WORKSHOP.md:490-492`） |
| 版本区间 | 我们已有 `app` 区间（`docs/PACKS.md:62`）；Forge 额外的 `api`/`game` 只保留 `game` 这类「针对哪个上游版本」的信息即可，不要引入 ABI |
| 工具链 | `tools/packs.mjs check` 与装载器必须用**同一个**规范化函数，否则会出现「check 通过、装不上」 |
| 测试沙箱 | 本机 `node --test` 必然 `spawn EPERM`；验收一律 `node <testfile>`，CI 侧不受影响 |
| 文档约束 | 新增文档页/引用尚未存在的模块可能触发 `test/docs-consistency.test.js` / `docs-paths`；`docs/PACKS.md` 的改动要与 `shared/packs.js` 同批 |
| 偏离 Forge 的自觉 | 「包 = 清单点名的文件」（不是 Forge 的「目录全部文件」）是**有意**偏离，理由（我们不执行包代码）必须写进 `docs/PACKS.md` |
| 逐字节重建测试 | `test/data.test.js:866` 要求离线重建复现 `data/`：**任何**把合并结果写回 `data/*.json` 的方案都会红 ⇒ 只能内存叠加 |
| 发布包清单 | `tools/package.mjs:89 RUNTIME_DIRS` 是显式清单：第三方包若不进发布包，就既不能提交、也不能加进清单（`docs/PACKS.md:161-163` 已是「只带已提交」） |
| 文档索引 | 新增 DESIGN 小节必须同批改 `docs/DESIGN.md` 的行，否则 `test/docs-paths.test.js` 红；`docs/PACKS.md` 自身不受该约束 |

## 9. 交叉复核补充（Forge 侧 + 我们这侧逐行核对结果）

这一节是把两侧源码逐行核对后补进来的实现细节，写代码时按这里抄，不要凭印象。

### 9.1 Forge 的「数据层」其实不含任何执行

- `shared/workshop.js`（3,744 行）**没有任何执行**：它只做清单/内容文件的形状校验与叠加合并，连 `import()` 都没有；`kits` / `client.panels` / `server.*` 只是被**校验声明形状**（`parseClientDecl:501`、`parseServerDecl:780`）。
- 执行发生在 `server/workshop.js`：`loadWorkshopKits:1105-1283`（`await import()` 在 `:1222`）、`loadWorkshopHooks:1285-1370`（`:1321`）、`dropUnavailablePreDispatchPacks:1372`。⇒ 把**共享层的数据规则整套搬走、把装载层的执行部分整段丢掉**，在 Forge 里也是一条干净的切线。
- `shared/modSurface.js`（424 行）在发行包里是**死代码**（只有未随包发布的 `test/modSurface.test.js` 引用它）⇒ 我们完全不需要它。`shared/kitImports.js`（407 行）只被执行的 kit 路径用（`relativeModuleUrl:1055`、`loadWorkshopKits`），**身份摘要不需要它**。
- `shared/workshop.js` 的传递依赖里有一条要小心：它 import `shared/protocol.js` 只为 `C2S`（`:182`，用于 `PRE_DISPATCH_INTERCEPTS` `:423`）。我们丢掉 `server` 字段的同时把这两处一起删，就不会把 56 KB 的 protocol 拖进新模块。

### 9.2 合并顺序与记录级合并（必须照抄的语义）

- 叠加顺序**不是** layer A/B/C，而是 `byPackId`：按包 id 的 UTF-16 码元升序（`shared/workshop.js:2321`，用于 `:2661`）。**id 小的赢**每一次冲突。
- 记录级四条判定（`mergeOne` 回调 `:2668-2708`）依次是：① 别的包已贡献过同一 `<file>:<id>` ⇒ `PACK_ID_COLLISION`（后来的输，**即使它声明了覆盖**）；② 官方已有该 id 且本包没在 `overrides` 里点名 ⇒ `OFFICIAL_ID_COLLISION`（保留官方）；③ 声明了覆盖但补丁里有官方记录不存在的键 ⇒ `UNKNOWN_OVERRIDE_FIELD`（闭世界）；④ 否则新增/覆盖。覆盖时是 `mergeRecord(priorMap[id], rec)`（`:2707`）——叠加在「官方或更早那个包的记录」上，不是叠加在 `base` 上。
- `mergeRecord(base, patch)`（`:2417-2430`）是**字段级递归**：`OVERRIDE_REPLACE_KEYS = [skill, skills, trait, traitBase, traitOverride, modules, rangeGrid, attackRangeGrid, assets, diy, bonds]`（`:2378`）或值本身是数组 ⇒ **整段替换**；`OVERRIDE_KEYED_LISTS = {talents:"index", talentsBase:"index", talentChanges:"talentIndex"}`（`:2407`）⇒ 按整数 id 配对合并、base 顺序保留、补丁多出的追加；**任一侧键重复时整表退回整段替换**（`:2449-2458`）。
- 内容文件规范化 `normalizeContentFile`（`:2012-2033`）：必须是普通对象（`BAD_CONTENT`）、键匹配 `RECORD_ID_RE = /^[A-Za-z0-9_\-.:]{1,64}$/`（`BAD_RECORD_ID`）、值为普通对象（`BAD_RECORD`）、记录自带 id 字段时**必须等于键**（`ID_MISMATCH`，映射表 `ID_FIELD_BY_FILE` `:33-37`）、空文件 `EMPTY_CONTENT`。
- `EMPTY_PACK`（`:1847-1862`）在**所有**贡献项解析完之后判；`support` / `playtest` 明确不算贡献项（`fx.silentPhases: []` 也不算，`:1840`）。
- 合并后还有一串**后处理**，顺序是有意的（`:2713-2738`）：linkStages → voices → bondIcons → itemIcons → art → flatArt → skins → forms → fx → support → operators。我们只搬用到的那几支（`linkWorkshopStages:3658-3678` 会把新 stage 追加进 `config.modes[m].stages`；`config` 本身永不被包贡献）。
- 装载器把坏包**跳过并报告**、绝不抛（`server/workshop.js:87-223`）：`pack.json` 缺失/坏 JSON ⇒ 跳过该包；某个内容文件坏 ⇒ 只跳过那个文件，包其余部分照常；冒烟日志形如 `[workshop] applied N pack(s): …` 加每条 `[workshop] <pack>: <reason>`。

### 9.3 身份摘要（byte-compatible 配方）

1. `pack.json`：哈希的是**规范化后的清单对象的 canonicalJson**，不是磁盘字节（`server/workshop.js:834`）⇒ 两种写法得到同一个摘要。
2. 每个**声明并成功解析**的内容文件：`canonicalJson(normalizedRecords)`（`:836`）——同样不是磁盘字节。
3. Forge 还会哈希**目录里每一个普通文件**的原始字节（`:846-851`，经 `server/packFiles.js:42 listPackFiles`：递归、按路径码元排序、符号链接既不跟随也不列出、**无任何排除**）。⇒ 我们**有意偏离**：只哈希清单点名的文件（我们不执行包代码，「没被声明就不算」在这里是安全的）。这条偏离必须写进 `docs/PACKS.md`。
4. `canonicalJson`（`shared/modIdentity.js:168-174`）：标量 `JSON.stringify`，数组 `[a,b]` 无空格，对象键先过滤掉 `undefined` 再 `.sort()`，`"k":v` 无空格。`modManifestDigest`（`:182-188`）：`[path, hash]` 对的数组 → 按 path 排序 → `sha256Hex(canonicalJson(pairs))`。`sha256Hex`（`:122-160`）是手写 sha256（为了浏览器不依赖 `node:crypto`/`TextEncoder`）——我们用 Node 的 `createHash("sha256")` 结果一致。
5. **哪些键「显式为 null」和「根本不出现」会改哈希**：`normalizePackManifest` 会显式写 `api: null` / `layer: null` / `combat: null`，而 `assets/client/server/routes/i18n/notices/forms/fx` 只在字段真的出现时才写进对象（`:1817-1826`、`:1961`、`:1967`）。我们的实现必须把这个不对称也定下来（否则同一个包两种写法的摘要不同）。
6. 哨兵路径 `assets.container.sha256`（`server/packFiles.js:28`）只服务 `assets` 类型，我们不搬。

### 9.5 我们的 `data` 类型该带哪些字段（收敛后的结论）

照 §9.2/§9.4 的切线，`packs/<id>/pack.json` 的 data 类型字段就是：`type` / `id` / `name` / `englishName` / `version` / `app`（我们已有）+ `content`（角色名单）+ `overrides` + `license`/`authors`/`credits`（声明用）。**`game` 可选**（记「针对哪个上游版本」），**`api` 不要**（没有代码就没有 ABI）。其余 Forge 字段（`assets`/`client`/`server`/`routes`/`i18n`/`notices`/`forms`/`fx`/`voices`/`voiceLangs`/`bondIcons`/`itemIcons`/`art`/`skins`/`support`/`operators`/`playtest`/`layer`/`combat`/`hasAssets`）**一律拒绝**，并给出「本类型不支持该字段」的点名错误而不是静默忽略 —— 这正是 Forge `PACK_UNKNOWN_FIELD` 的用意（`docs/WORKSHOP.md:80-90`：静默读过去会让作者以为生效了）。
