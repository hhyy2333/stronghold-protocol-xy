# 会话归属路由（D 层）设计稿 —— 蓝绿翻槽后，重连回到原槽

> 状态：**设计，未实现**。对象：本仓 0.19.3（APP 0.19.3 / UPSTREAM 0.3.0）+ 双槽蓝绿部署。
> 参考实现：jingjiangze/stronghold-ws-compression 的 integration/server/sessionDirectory.js 与
> integration/server/http/routeForward.js。**本稿只借它的路由思想，不搬它的目录层**（见 §13）。
> 落点：先在 04-文档/ 存着；实现后按「文档跟代码」的规矩，把规范性描述挪进

## 1. 要解决的失败（现状）

蓝绿发布的语义（05-部署/sp-release.sh 头部注释）是：**旧槽上已建立的 WebSocket 不被切断，
进行中的对局在旧进程里照常打完**。但会话表是**进程内存**的：

- app/server/net.js 的 SessionRegistry：token → Session，重连窗口 5 分钟（solo 另设 24 h）；
- 翻槽只改 nginx upstream；旧槽继续跑，最多等 DRAIN_TIMEOUT（默认 1800 s）再停。

于是翻槽之后，**旧槽上的玩家只要发生一次新 socket**：

| 触发 | 结果 |
|---|---|
| F5 / 页面崩溃后自动重载 | 新 socket → nginx → **新槽** → 不认识 token → 新开会话 |
| 手机切 Wi-Fi↔4G、休眠唤醒、后台标签被回收 | 同上 |
| 客户端自动重连（public/js/net.js 指数退避） | 同上 |

客户端会弹「服务器会话已重置，上一局模拟已结束」（public/js/store.js:184 sessionResetNotice）。
旧槽里那一局还在跑，但它的主人永远回不去了；5 分钟后该会话按掉线处理。

**这不是理论风险**：05-部署/0.19.3-发布记录-20261018.md 写着切流时旧槽仍有 **21 人 / 11 局**。

---

## 2. 目标与非目标

**目标**：翻槽后的排空窗口内（以及回滚时反向），一个**已存在会话**的重连/刷新，被送回**拥有该会话的槽**，
由它自己完成 hello → resume。玩家侧表现为：对局不丢，最多一次正常的重连。

**非目标**：

- 不省带宽、不改压缩、不影响新连接的性能；
- 不救「拥有会话那个进程重启/崩溃」——Match 状态本来就在内存里，丢了就丢了（D 只解决**路由**）；
- 不做负载均衡、不做跨机、不做 Match 状态迁移。

## 3. 方案总览

   浏览器 ──wss──> nginx :80 ──upstream──> 当前槽 B(3001)
                                          │
      /ws?cred=v1.xxxx.yyyy ──────────────┤ 验签 + 查存活 → 指向 A？
                                          │        ├─ 是 → 原始 upgrade 字节 TCP splice 到 A(3000)
                                          │        │        A 自己 handleUpgrade → hello{token} → resume
                                          │        └─ 否/失败 → 本机 handleUpgrade（今天的行为）

一句话：**cred 说「这个会话属于哪个槽」，存活文件说「那个槽现在还活着、还是不是同一个实例」，
新槽只做一次转发；任何不确定都回落为本机处理。**

## 4. 四个新件

### 4.1 cred：签名的小凭据（新增 app/server/sessionRoute.js，约 90 行）

格式（放 URL query，恒长可控）：

    v1.<base64url(payload)>.<base64url(HMAC-SHA256(payload, SP_ROUTE_SECRET))>
    payload = {"s":"a","i":"7f3c9a1b","e":1760000000000}
               ↑槽   ↑本进程实例 id  ↑过期时刻(ms)

- **签发**：welcome 里多一个字段 cred（app/server/net.js:914 那一行，含 resumed 的那份对象）。
  每个进程一个实例 id（boot 时 randomBytes(6).toString('hex')），每份 welcome 现签（HMAC 很便宜）。
- **校验**：timingSafeEqual；payload 里**没有 token、没有端口**——端口由服务端从 SP_ROUTE_PEERS 解析，
  客户端永远不能指定一个端口。
- **过期**：e 到期即拒（建议 24 h，与 solo 重连窗口同量级；真正的护栏是 §4.2 的实例校验）。
- **为什么放 URL 不放 hello**：hello 是严格校验的 C2S 帧，加未知字段会让**老服务端整条拒**；
  URL query 老服务端根本不看。这是滚动发布里「新旧版本同时在跑」的必要条件。

### 4.2 存活文件：/var/lib/stronghold/route/<slot>.json（约 40 行）

    {"slot":"a","i":"7f3c9a1b","port":3000,"at":1760000000000}

- 每槽每 15 s 原子写一次（tmp + rename），与 announceStore / banStore 同一套写法；
  **必须放在槽目录外**——蓝绿发布整份替换 /opt/Stronghold-Protocol-*，放里面就没了（/etc/stronghold.env 的教训）。
- 读方缓存 ≤2 s；at 超过 60 s 视为**不存活**，不转发。
- 为什么需要它：
  - A 停了 → 文件很快变旧 → 之后带旧 cred 的连接直接本机处理（不必等一次失败的 loopback connect）；
  - A 被重启成新进程（发布时准备空闲槽就会发生）→ 实例 id 变了 → 旧 cred 的 i 对不上 → 不转发。
    **没有这一条，一个躺了一天的旧 cred 会把连接送进一个完全不同版本的空闲槽。**

### 4.3 upgrade 钩子（改 app/server/http/websocket.js 的 attachWebSocket，约 20 行）

插入点在**路径/lane 判定之后、network.admission 之前**（websocket.js:277-279 之间）：

    server.on('upgrade', (req, socket, head) => {
      socket.on('error', () => {});
      const parts = splitUrl(req.url || '/');
      const lane = parts.rawPath === '/ws' ? null : resolveLane(parts.rawPath, table.lanes);
      if (!lane && parts.rawPath !== '/ws') { reject(404, 'Not Found'); return; }
      const continueLocally = () => { /* 现有 admission → narrowDeflateOffer → wss.handleUpgrade 整段 */ };

      if (!lane && route?.enabled()) {
        const cred = route.credentialFromQuery(parts.query);   // 同步、纯字符串
        const target = route.forwardTargetFor(cred);           // 同步：验签 + 缓存读存活 + 防自环
        if (target) {
          // 异步只为那次 loopback connect；成功即交接 socket，失败原样回落
          route.forward(req, socket, head, target).then((ok) => { if (!ok) continueLocally(); });
          return;
        }
      }
      continueLocally();
    });

顺序的三条理由：

1. **转发在 admission 之前**：admission（封禁 / per-address / 满员）是**归属槽**的决定。B 若先跑自己的
   admission，会用 B 的计数去拒一条本该由 A 服务的连接（例如 B 满员而 A 有空位），而且会把这条连接
   记到 B 的账上、实际却不在 B。A 收到回放的原始请求后会自己跑 admission → 行为与今天完全一致。
2. **lane 不参与**：lane 是宿主注册的独立路径，永不转发（websocket.js:285-293 原样）。
3. **失败回落必须是无损的**：forward() 在成功 socket.pipe(up) 之前不得给客户端 socket 挂任何监听、
   不得读它；失败时 socket 仍处于暂停态、head 仍完整，handleUpgrade 可以照常接手。
   参考包的 forwardUpgrade 就是这么写的，**建议原样移植，不要重写**。

### 4.4 客户端（改 app/public/js/net.js，约 30 行）

- defaultWsUrl() / connect()（net.js:116-119、:253-256）：拼 URL 时带上
  cred=${encodeURIComponent(cred)}；没有 cred 就原样。
- 收到 welcome 时保存 msg.cred，**按 token 哈希存**（net.js:751-757 已有 tokenHash() 与
  sp.tokens 最近 token 列表）：

      sp.cred = { "<tokenHash>": "v1.…" }     // localStorage，随 sp.tokens 同步裁剪（最多 4 条）

- 连之前按「本次 hello 将要用的 token」查这个映射。账号模式（SP_ACCOUNTS=1）下 token 由服务端决定，
  逻辑不变：welcome 里还是会带 cred。
- 老客户端（不认 cred 字段）只是不带参数 → 行为与今天一致；新客户端连老服务端 → 没有 cred → 同样一致。
  **不需要顶 PROTOCOL_VERSION**（welcome 加字段是向下兼容的；顶号的判据是「旧页面会读错」）。

## 5. 生命周期与边界

| 事件 | 行为 |
|---|---|
| 翻槽后旧槽上的会话重连，带 A 的 cred | B 验签 → 存活文件显示 A 活着、实例一致 → splice 到 A → resume |
| 客户端刷新（F5） | 同上（cred 在 localStorage，刷新不丢） |
| 关标签页再打开（重连窗口内） | 同上（cred 跟着 token 一起恢复） |
| A 已停 / 存活文件过期 | 本机建新会话（今天的行为），不等待 |
| A 被重启成新实例 | i 不匹配 → 本机处理 |
| cred 过期 / 签名不对 / 槽名未知 / 目标端口==自己 | 本机处理 |
| SP_ROUTE 未配置 | 整段不进入，**零代码路径** |
| 回滚（upstream 切回 A） | 对称成立：B 上的新对局重连回 B |
| 新连接（无 cred） | 完全走今天的分支 |

    SP_ROUTE_SLOT=a|b                     # 本槽身份

## 8. 可观测性

- /healthz 增加（**只对 loopback 请求**，沿用 /healthz?traffic=1 的 isLocalIp 规矩，routes.js:376）：

      "route": { "enabled": true, "slot": "b", "instanceId": "7f3c…", "peers": { "a": "fresh" },
                 "forwarded": 12, "fallback": 3, "refused": 0 }

- 计数器的意义：forwarded > 0 就是「这层真的在救对局」；fallback 在 A 停之后应当归零。
- 日志：首次转发 info 一次；peer 不可达 warn（按 5 s 限流，别每连接一条）。

## 9. 安全

| 面 | 处置 |
|---|---|
| cred 是不是凭证 | **不是**。说话的是 hello.token；cred 只影响「这条连接由谁服务」，泄露只暴露槽名 |
| 客户端指定端口 | 不可能：payload 只有槽名，端口由服务端 SP_ROUTE_PEERS 解析 |
| 伪造 | HMAC-SHA256 + timingSafeEqual；伪造最多把**自己的**连接送到一个槽，签名不过就不转 |
| 自环 | 目标端口 == 自己监听端口 ⇒ 不转发 |
| 头部注入 | 回放原始 rawHeaders；只在 X-Forwarded-For 末尾追加**解析出的 IP 字面量**，非 IP 一律丢弃（参考包已这么做） |
| per-address 限额 | 回放后 A 的 clientAddress 读**最右一段** XFF（net.js:494-497），拿到 B 解析出的真实客户端地址 —— 与 A 直接收到时同一个 key |
| 放大 | 只有签名有效的 cred 才触发一次 loopback connect；无外部依赖、无递归 |
| 日志 | nginx access log 里会出现 ?cred=…（槽名+实例+到期）；它不是秘密，但**不要**把 token 写进 URL |

## 10. 测试

**单元**（app/test/route-ownership.test.js）：

- cred：签发/校验往返、改 payload、改签名、过期、错 secret、非字符串、超长；
- query 解析：?cred=、URL 编码、重复参数取第一个、形状不对返回 null；
- 存活文件：fresh / stale / 缺失 / 坏 JSON / 实例不匹配 / 原子替换；
- forwardTargetFor：自己端口、未知槽、SP_ROUTE_PEERS 没配、cred 指向本槽。

**两进程 e2e**（同一文件，两个真实 startServer({ host:'127.0.0.1', port })）：

1. **验收线**：在 A 上建会话拿 token+cred；用 ws://B/ws?cred=<A 的 cred> + hello{token} 连 →
   welcome.resumed === true、playerId 不变；
2. 不带 cred → 新 playerId（证明回退分支没变）；
3. 关掉 A → 带 cred 连 B → <500 ms 落到本机、新 playerId、不挂起；
4. A 换实例 id（模拟重启）→ 旧 cred 不转发；
5. 坏签名 / 伪造槽名 / 目标端口=自己 → 不转发、正常建会话；
6. 同一 IP 并发超过 maxConnectionsPerAddr → A 侧仍返回 429（XFF 真的生效）；
7. 非 /ws 路径与 lane 完全不受影响。

**回归**：test/net-socket.test.js、test/ws-compression.test.js、test/net-compression.test.js、
test/client-identity-*.test.js，以及 sp-release.sh 的 ws_check（普通 + 挑剔两个客户端）。

> 本机蓝绿端到端 harness（_probe/bluegreen/run.mjs，sp-release.sh 注释里提到 14/14）
> **不在本工作区**（在废弃 repo 归档里）。§10 的两进程 e2e 就是它的最小替代，建议重建。

## 11. 上线三步（每步可独立回滚）

1. **只签不发**（SP_ROUTE 缺省 off）：cred 签发 + 客户端携带 + 存活文件 + 计数器 + 「would forward」日志。
   验收：全量测试绿；welcome 多一个字段；老客户端无感；线上无行为变化。
2. **只在新槽开转发**：它负责把连接送回旧槽（A 侧不需要这项能力）。演练：A 起会话 → sp-release.sh 切到 B → 对局中 F5 →
   日志 route forwarded、welcome resumed:true、对局继续。
3. **两槽全开 + 发布脚本检查**：观察一周 forwarded/fallback；fallback 在 A 停了之后应归零。

回滚：SP_ROUTE=off 或删掉 env 即完全回到今天（客户端 URL 上多一个没人校验的参数，无副作用）。

## 12. 风险

| 风险 | 缓解 |
|---|---|
| upgrade 路径前置代码的 bug 影响所有 /ws | 仅带 cred 的连接进入；off 时零路径；失败一律回落；e2e 覆盖回退分支 |
| 转发等待（建议 300–500 ms）延迟首帧 | 只在 A 已死/异常时出现；超时即回落 |
| 双槽版本不一致（新 B 转发、旧 A 不签发 cred） | 先发第 1 步到两槽，再开转发；旧 A 的客户端没有 cred ⇒ 退化为今天 |
| 连接/流量计数口径变化（转发连接记在 A、不记在 B） | 面板注明；forwarded 单独计数 |
| 回滚时反向丢局 | 对称支持（B 发出的 cred 路由回 B），无需额外代码 |
| nginx 日志出现 cred | 无 token、无端口；如需可换成别的载体，但 WS 升级头同样进日志 |

## 13. 明确不做

- **不搬**参考包的 sessionDirectory.js（283 行：token 哈希目录、租约、恢复截止）——两槽同机、
  槽停即会话亡，用不上；本稿的 cred + 存活文件 ≈ 130 行就能覆盖同一场景。**将来跨机再谈目录**。
- 不做 Match 状态迁移、不做共享 SessionRegistry（证明不了对局在哪，最后还是要把连接送过去）。
- 不动 hello 字段、不顶 PROTOCOL_VERSION、不改压缩参数。
- 不把 /ws 变成负载均衡：**只在 cred 明确指向另一个活着的槽时**转发。
