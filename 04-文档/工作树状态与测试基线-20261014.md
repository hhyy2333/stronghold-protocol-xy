## 3. 48 条红的根因分类

### 3.1 依赖装坏（约 40 条，`npm ci` 可修）

**证据**：

```
$ node test/custom-art.test.js
  "char_9002_yana spine/front: Cannot find module './core/attachments/Attachment.js'
   Require stack: .../node_modules/@pixi-spine/runtime-3.8/lib/index.js"

$ node test/assets.test.js
  Error: Cannot find module '@pixi/core'
```

**根因**：`node_modules/@pixi/*` **整体缺失**——`node_modules/@pixi` 目录是空的，而 `package-lock.json` 里 `@pixi/core@7.4.3` 等条目都在。`@pixi-spine/runtime-3.8/lib/core/` 也只剩 `vertexeffects`。

**影响面**：所有 Spine / 渲染 / 素材校验类用例（`custom-art`、`assets`、`impostor-bounds`、`eyelids` 等）。

**修法**：`npm ci`（**不要**用 `npm install`，会改 lockfile）。

#### 3.2.1 #4 的根因：两条不变量实现漂移（不是「卡池被抽坏」）

我一开始判成「共享卡池被抽成负数」，**这个判断不准确**。逐行比对后真相是：

```
server/match/invariants.js  (权威实现)
  HEAD:  if (!(e.left >= 0 && e.left <= e.cap)) fail(`pool ${base}: left ...`);
  now :  if (!(Number.isInteger(e.left) && e.left <= e.cap)) fail(`pool ${base}: balance ...`);
                                        ^^^^^^^^^^^^ 只查整数与上界，**不再查 >= 0**

test/match/harness.js  (镜像实现)
  HEAD:  assert.ok(e.left >= 0 && e.left <= e.cap, ...);
  now :  assert.ok(e.left >= 0 && e.left <= e.cap, ...);   ← 一字未改
```

而 `test/match/harness.js:176` 自己的注释写着：

> *The original harness checks (kept alongside `collectViolations`; **they must agree**).*

**所以漂移的是 `harness.js` 这一侧**：`invariants.js` 已被放宽为允许 `left < 0`（其第 204-205 行的注释解释了原因：*「Fixed operator gifts may overdraw equipment stock… The chess pool above also permits explicit overdraw (Mimic)」*），而镜像实现还在断言 `left >= 0`。

这与 Forge `PS100-MIGRATION.md §11.4` 第 1 条**一模一样**：那边也是 `harness.js` 的 `legacyInvariants` 漂移，修法是**把镜像实现改成与权威侧同口径**（并加「两种模式都不丢牙齿」的断言，只加强不放松）。

> **这条红是「测试没跟上代码」，不是玩法 bug。** 但它仍然必须修——一条永远红的断言会让后续所有验证失去意义。修法：`harness.js:248` 改为与 `invariants.js:198` 同口径（`Number.isInteger` + 上界），并保留「负数仍被抓」的独立断言。
